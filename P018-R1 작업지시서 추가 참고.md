---

# 0. 문서 목적

본 문서는 약 100M parameter급 autoregressive language model을 대상으로 수행하는 **P018-R1 학술 실험 및 학술자료화 작업**의 통합 작업 지시서다.

목표는 다음과 같다.

1. 기존 repository의 실제 architecture를 코드 수준에서 검증하고,
2. 기존 P018 실험의 methodological confound를 제거하고,
3. Dense teacher와 parameter-shared/Tied teacher의 KD 효율을 동일 조건에서 비교하며,
4. teacher parameter 및 GPU memory reduction과 student quality 사이의 trade-off를 정량화하고,
5. 기존 선행연구와 정확하게 비교하여 novelty와 한계를 판단하고,
6. 결과가 가설을 지지하거나 반박하는지와 관계없이 재현 가능한 empirical study / technical report / 논문 형태로 정리한다.

# 1. NON-NEGOTIABLE RULES

다음 규칙은 전체 실험에서 반드시 준수한다.

## Rule 1 — 코드에 없는 architecture를 추측하지 않는다

실험 이름, preset 이름, 기존 대화 내용만으로 architecture를 추론하지 않는다.

예:

```text id="v23_r1"
m100R1c
mC_wsd
mC_ct
dense
```

등의 이름을 보고 hidden size, layer count, FFN 구조, sharing pattern 등을 추측해서는 안 된다.

반드시 실제 repository source code와 configuration을 읽고 **effective architecture**를 확정한다.

---

## Rule 2 — Primary experiment에서 Dense → Tied compression을 사용하지 않는다

Primary experiment에서는 Dense teacher를 먼저 학습하고 이를 Tied teacher로 압축하는 방식이 아니라,

```text id="v23_r2"
Dense Teacher ──→ Student D

Tied Teacher  ──→ Student T
```

두 teacher를 **동일한 조건에서 독립적으로 처음부터 학습**한다.

Dense→Tied compression은 별도의 optional ablation으로만 수행한다.

---

## Rule 3 — Primary comparison의 training budget은 사전에 고정한다

실험 결과를 본 후 teacher quality를 맞추기 위해 다음을 변경해서는 안 된다.

* training tokens
* token pool
* training steps
* learning rate
* scheduler
* batch size
* gradient accumulation
* dataset
* seed

추가 token-budget matching experiment는 사전에 정의된 별도의 ablation으로만 수행한다.

---

## Rule 4 — Equal-data budget과 equal-compute budget을 구분한다

Primary experiment는 **equal-data / equal-optimization-step budget**을 기준으로 정의한다.

즉 다음을 동일하게 유지한다.

* same dataset
* same token count
* same sequence length
* same optimizer
* same number of optimization steps

다음은 동일하지 않을 수 있으며, 별도 분석 항목이다.

* forward FLOPs
* backward FLOPs
* wall-clock time
* latency
* peak memory

이 distinction을 논문과 실험 기록에서 명시적으로 유지한다.

---

## Rule 5 — Equivalence margin을 결과를 본 뒤 변경하지 않는다

Teacher/student quality equivalence margin (\delta)는 primary experiment 전에 정의한다.

결과가 margin을 만족하지 않는다고 해서 사후적으로 (\delta)를 변경하지 않는다.

---

## Rule 6 — Teacher quality mismatch는 실패가 아니다

Tied teacher가 Dense teacher보다 성능이 낮더라도 결과를 폐기하지 않는다.

Teacher quality degradation 자체가 parameter sharing의 중요한 empirical result다.

---

## Rule 7 — Memory reduction과 compute reduction을 동일시하지 않는다

다음을 서로 독립적인 측정값으로 취급한다.

```text id="v23_r7"
parameter reduction
memory reduction
training compute
training wall-clock
inference latency
student training cost
```

---

## Rule 8 — 결과를 사전에 정한 결론에 맞추지 않는다

결과가 H1~H8 또는 NQ1을 지지하는지 반박하는지와 관계없이 그대로 보고한다.

# 2. 기존 P018의 methodological background

기존 P018에서 다음 결과를 관찰했다.

```text id="v23_bg1"
dense KD teacher validation loss = 3.8080

mC_wsd validation loss = 3.6984

paired difference = +0.1096 nats

mC_wsd teacher → mC_ct student = 3.6764

기존 mC_wsd student 대비 = −0.0220 nats
```

또한:

* compressed/tied teacher 사용 시 peak/reserved GPU memory 감소
* 정상상태 training speed는 사실상 동일

이라는 결과를 관찰했다.

그러나 다음 confound가 존재했다.

```text id="v23_bg2"
dense = 300M training-token pool
mC_wsd = 600M training-token pool
```

기존 실험에서 300M → 600M token pool 증가 자체로 약 0.12 loss 개선이 관찰되었다.

따라서 기존 P018의:

```text id="v23_bg3"
dense → mC_wsd
+0.1096 nats
```

차이를 architecture superiority의 증거로 해석하지 않는다.

또한 기존 P018은 seed=1 중심의 실험이므로 일반화된 결론을 내리지 않는다.

---

# 3. 기존 P018에서 얻은 추가 methodological lessons

## Lesson A — Token-pool confound

300M vs 600M token pool 차이는 architecture effect와 분리해야 한다.

---

## Lesson B — Same-family / self-distillation lineage confound

기존의 `mC_wsd → mC_ct` 계열 결과는 동일 architecture family 또는 같은 lineage를 공유하는 self-/same-family distillation 성격을 가질 수 있다.

따라서 이 결과는 일반적인 teacher-student KD 효과와 parameter-sharing 효과를 완전히 분리해서 설명할 수 없다.

P018-R1에서는 Dense/Tied teacher를 독립적으로 학습하고, 동일한 student initialization 및 동일 KD protocol을 사용하여 **teacher 구조의 차이**를 주요 독립변수로 취급한다.

---

## Lesson C — Memory accounting discrepancy

기존 P018에서 memory accounting 방식에 discrepancy가 있을 수 있으므로, R1에서는 memory metric의 정의를 실험 전에 고정한다.

최소한 다음을 분리한다.

* peak allocated memory
* peak reserved memory
* model parameter memory
* optimizer memory
* activation memory

서로 다른 measurement protocol의 값을 직접 비교하지 않는다.

# 4. P018-R1의 핵심 연구 질문

Primary research question:

> **Can a parameter-shared teacher provide comparable knowledge-transfer quality to a dense teacher while substantially reducing teacher parameter and GPU-memory requirements?**

한국어:

> **Parameter-shared teacher가 dense teacher에 준하는 knowledge-transfer quality를 유지하면서 teacher의 parameter 및 GPU-memory 요구량을 얼마나 줄일 수 있는가?**

연구의 중심은 새로운 Transformer architecture 자체가 아니다.

핵심은:

> **parameter-shared teacher의 memory-efficient knowledge distillation efficiency**

이다.

---

# 5. 연구 가설

## H1 — Teacher parameter compression

Tied teacher는 Dense teacher보다 unique/trainable parameter 수가 작다.

---

## H2 — Teacher memory reduction

Tied teacher는 Dense teacher보다 teacher GPU memory footprint가 작다.

이때 memory footprint는 다음을 구분해서 해석한다.

* training memory
* inference/KD memory
* allocator reserved memory

---

## H3 — Teacher quality preservation

동일 training budget에서 Tied teacher가 Dense teacher와 사전 정의된 equivalence margin 내의 validation quality를 유지하는지 검증한다.

[
|L_{teacher,tied}-L_{teacher,dense}| < \delta
]

---

## H4 — KD quality preservation

동일 student architecture와 KD 조건에서 Tied teacher를 사용한 student와 Dense teacher를 사용한 student의 validation loss 차이가 사전 정의된 equivalence margin 내인지 검증한다.

---

## H5 — Teacher memory advantage

Tied teacher의 peak allocated/reserved GPU memory가 Dense teacher보다 감소하는지 검증한다.

---

## H6 — Runtime neutrality

Parameter sharing 자체가 forward FLOPs를 감소시키지 않는 구조라면 runtime 개선을 가정하지 않는다.

Teacher-only forward latency와 complete KD step latency를 실제 측정한다.

---

## H7 — End-to-end efficiency

Tied teacher의 memory advantage가 teacher training cost 또는 기타 추가 compute에 의해 상쇄되는지 분석한다.

---

## H8 — Teacher-side efficiency novelty

선행연구 중 “dense teacher vs parameter-shared teacher”를 동일 budget에서 직접 비교하고, teacher memory와 student transfer quality를 함께 평가하는 기존 연구가 있는지 확인한다.

이 질문은 novelty 판단용이다.

# 25. Equivalence criterion

Primary experiment 전에 equivalence margin (\delta)를 정의한다.

예:

[
\Delta = L_{tied} - L_{dense}
]

그리고 95% confidence interval을 계산한다.

Practical equivalence는 다음을 만족하는 경우로 정의한다.

[
CI_{lower} > -\delta \quad \text{and} \quad CI_{upper} < +\delta
]

가능하면 TOST(Two One-Sided Tests)를 사용한다.

중요:

* (\delta)는 결과를 보기 전에 정의한다.
* 결과를 본 뒤 margin을 변경하지 않는다.
* measurement noise와 practical equivalence margin을 동일시하지 않는다.

# 49. 최종 원칙

P018-R1의 목적은 다음과 같은 결론을 만들어내는 것이 아니다.

> “Parameter sharing is better.”

또는:

> “Tied teacher is better than dense teacher.”

실험의 목적은 다음을 통제된 조건에서 측정하는 것이다.

```text id="v23_final1"
Parameter sharing
       ↓
Teacher parameter reduction
       ↓
Teacher memory reduction
       ↓
Teacher quality change
       ↓
Knowledge-transfer change
       ↓
Student quality change
       ↓
Training/runtime trade-off
```

최종적으로 다음 질문에 empirical evidence로 답한다.

> **How much teacher memory can parameter sharing remove, and what—if anything—is the resulting cost in teacher quality, knowledge transfer, student quality, training compute, and runtime?**

결과가 긍정적이든 부정적이든 모두 연구 결과로 기록한다.
