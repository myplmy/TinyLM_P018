## 2. 2026-08-06 신규 항목

- **★★풀 크기가 val 셋을 바꾼다(L5 + L4, 결과 006 §5).** `prepare()` 의 val 은 **스트림
  말미 0.5%** 이고(`arr[-n_val:]`), 한국어 위키는 약 300M 토큰에서 **고갈**된다. 둘이 겹쳐
  **val 한글 비율이 300M 풀 13.5% / 600M 5.5% / 1200M 0.0%** 가 됐다.
  → **풀이 다른 런의 `val_loss`·`bpb` 비교는 무효다. 시험지가 다르다.**

  `bytes_per_token_val` 을 병기한다. **구 캐시 수치를 인용할 땐 보정하거나 보정 불가를 명시한다.**
- **★"같은 300M 토큰" 은 같은 조건이 아니다 — 다국어에서는 언어별 예산이 조건이다(결과 011 §1).**

> **이 저장소의 사고는 자꾸 "같은 이름, 다른 물건" 에서 난다.**

### 29. OOM 이 OOM 이라는 이름으로 오지 않는다 (결과 037 §7.2)

`torch.OutOfMemoryError` 는 **PyTorch 가 직접 하는 할당**에만 뜬다.
cuBLAS·cuDNN 은 **자기 workspace 를 GPU 에 따로 잡고**, 그게 실패하면

```
RuntimeError: CUDA error: CUBLAS_STATUS_EXECUTION_FAILED when calling `cublasGemmEx(...)`
```

로 나온다. **같은 원인(메모리 부족)이 다른 창구에서 다른 이름으로** 나타난 것이다.

> **규칙: 메모리 여유가 1GB 미만인 런에서 CUDA 오류가 나면 OOM 계열부터 의심한다.**
> 확인법 = 같은 명령을 **단독·유휴 상태로 재실행**. 성공하면 환경·타이밍이다.

### 30. 스필은 조용하다 (결과 037 §4.1, 034 §10.3)

`mC_ct250_nockpt` 는 **종료코드 0, `skip 0`, 손실 정상**으로 끝났다. 그런데 **+26.4% 느렸다.**
로그 어디에도 *"스필했다"* 는 말이 없다 — **누적평균 `ms/step` 을 구간 순간값으로 복원해야만** 보인다.

| 런 | reserved | p90/p10 | 실제 |
|---|---:|---:|---|
| `mC_tinf_nockpt` | **15.37** | **7.4%** | 정상, −20.5% |
| `mC_ct250_nockpt` | 14.95 | **48.5%** | **스필, +26.4%** |

★**VRAM 이 더 적은 쪽이 스필했다 — 총량으로 예측할 수 없다.**
