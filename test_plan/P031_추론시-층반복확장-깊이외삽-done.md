## 우리 구조에서 "층 반복"이 정확히 무엇인가 (먼저 정의)

`transformer.py` 를 보면 층 구성이 이렇다:

```
prelude 2층   : 각자 독립 MLP (pre_mlps)
middle 16층   : MLP 을 g층씩 공유 (mid_mlps = 16/g 개). ★어텐션은 층마다 독립★
coda 2층      : 각자 독립 MLP (coda_mlps)
CLA           : KV 를 owner 층(i - i%cla_group)이 계산해 공유
```

**중요**: 공유되는 것은 **MLP 가중치**뿐이고 **어텐션·norm 은 층마다 따로 있다.**
따라서 "g 를 추론 시 늘린다"는 것은 성립하지 않는다 — 층을 늘리려면 어텐션 가중치가 필요하다.

**성립하는 정의는 하나다: `middle` 16층 블록 전체를 R 회 통과시킨다.**

| R | 중간 통과 수 | 총 층-통과 | 성격 |
|---|---|---|---|
| 0.5 | 8 | 12 | **축소** — 추론 비용 절감 |
| 0.75 | 12 | 16 | 축소 |
| **1.0** | **16** | **20** | **학습된 상태(기준)** |
| 1.25 | 20 | 24 | 소폭 확장 |
| 1.5 | 24 | 28 | 확장 |
| 2.0 | 32 | 36 | 배증 |

메모리는 **전 R 에서 동일**하다(가중치 재사용). 늘어나는 것은 연산과 지연뿐이다.

## ★예측 — 정직하게: **저하 또는 붕괴가 유력하다**

| 근거 | 방향 |
|---|---|
| **각 층은 위치 특화 함수를 배웠다.** 층 i 는 "깊이 i 의 residual 분포 → 깊이 i+1" 변환을 학습했다. 층 2 에 층 17 의 출력을 넣는 것은 **학습 분포 밖** | 저하 |
| **residual norm 누적.** 통과 수가 늘면 residual stream 에 더해지는 양이 늘어난다. 최종 norm 이 있어 로짓 스케일은 잡히지만 중간 거동은 이동한다 | 저하 |
| **삼진 양자화로 표현 정밀도가 낮다.** 통과가 늘면 양자화 오차가 누적된다 | 저하(우리 특유) |
| **변동 깊이로 학습하지 않았다.** 깊이 외삽이 작동한 선행 연구는 전부 **반복 횟수를 랜덤화해 학습**했다 | 저하 — 이게 가장 결정적 |
| 타잉 자체가 이미 "반복 정제" 성격 → 비공유 모델보다 추가 반복에 관대할 수 있음 | 소폭 개선 가능 |

**정량 예측**: R=1.25 에서 개선 확률 낮음(~20%), R=2.0 에서는 **큰 저하 또는 발산 예상**.
val 이 4~6 대로 뛰거나 반복 붕괴가 심해질 가능성이 있다.

> **그래서 이 실험의 1차 가치는 "성공"이 아니라 **메커니즘 확인**이다.**
> 저하한다면 결과 006 이 관측한 "타잉 격차 = 용량 상한"에 **메커니즘을 붙일 수 있다**:
> 공유 층이 **위치별로 다른 함수를 배우기 때문에** 용량이 소진된다는 설명.

## 근거 (선행 연구)

- **Universal Transformer** (arXiv:1807.03819) — 층을 재귀 적용, ACT 로 동적 종료.
- **ALBERT** (arXiv:1909.11942) — cross-layer 파라미터 공유. 우리 MLP 타잉의 원류.
- **Recurrent depth / latent reasoning** (arXiv:2502.05171) — 재귀 깊이 모델을 **학습 시 반복 횟수를
  랜덤화**하면 테스트 시 반복을 늘려 성능을 올릴 수 있다고 보고. **"랜덤화 학습"이 전제**라는 점이
  우리 예측의 핵심 근거다.
- Looped Transformer 계열(길이 일반화·프로그래머블 계산) — arXiv id 는 착수 시 확인해 기록한다.

## 실험 설계 (학습 없음, eval 전용)

### 구현 (최소 변경)

- `TMTConfig` 에 `infer_repeat: float = 1.0` 추가.
- `transformer.forward()` 의 middle 구간을 `R` 회 순회. **결정할 점 두 가지를 명시적으로 다룬다**:
  1. **KV 재계산 여부** — 각 통과에서 CLA owner 가 KV 를 **다시 계산**(새 x 기준)하는 것이
     "층이 늘어난 것"의 충실한 유추다. 기본은 재계산. `--repeat-kv-reuse` 로 반대도 측정.
  2. **분수 R 처리** — R=1.25 면 16층 중 **앞 4층만 한 번 더**. 어디를 반복할지가 결과를 바꿀 수
     있으므로 **앞·뒤·전체균등 3가지를 비교**한다(같은 비용, 다른 배치).
- `eval`/`generate` 에 `--infer-repeat R` 플래그. **학습 경로는 건드리지 않는다**(기본 1.0).

### 측정 (모델 3개 × R 6종)

| 모델 | 이유 |
|---|---|
| `mA_g4s34_k4` (g4, 11.7MB) | 🏆 정본 후보. 그룹 4개 |
| `mC_g8_k4` (g8, 14.9MB) | 그룹 2개 — **공유가 강할수록 외삽이 잘 되는가?** 핵심 대조 |
| `p6d` (dense, 공유 없음) | **대조군.** 공유가 없으면 외삽이 더 나쁠 것이라는 가설 확인 |

- 지표: **val_loss**(100배치, 기존 eval 경로 재사용) + `tok/s`(비용) + **정성 프로브**(P029 재실행).
- `g8` 이 `g4` 보다 외삽에 관대하면 → **"공유 강도와 외삽 가능성은 양의 상관"** 이라는
  실용적 규칙을 얻는다. 이건 후속 설계(학습 시 랜덤화)의 방향을 정해준다.

### 판정

| 관측 | 해석 | 후속 |
|---|---|---|
| R>1 에서 val **개선**(> 2σ = 0.024) | **메모리 0 으로 품질을 사는 레버 발견** | 즉시 P032(학습 시 R 랜덤화)로 확대 |
| R>1 에서 val 소폭 저하(< 0.024) | 외삽이 "깨지지는 않는다" — 랜덤화 학습의 전망 있음 | 조건부 P032 |
| R>1 에서 **큰 저하·붕괴** | **위치 특화 확인.** 타잉 격차의 메커니즘 설명 | 원장에 기록, 확장 종료 |
| **R<1 에서 완만한 저하** | **품질/지연 다이얼 확보**(엣지 배포용) | P030 과 연결해 배포 옵션화 |
| g8 이 g4 보다 관대 | 공유 강도 ↔ 외삽 가능성 양의 상관 | 후속 설계 방향 확정 |

> **R<1 방향을 빠뜨리지 말 것.** 확장이 실패해도 **축소는 성공할 수 있다.**
> 엣지에서 "메모리는 그대로, 지연만 절반"은 실전에서 매우 유용한 옵션이다.
> 그리고 이쪽이 예측상 성공 가능성이 더 높다(학습된 깊이보다 얕게 가는 것이므로).

## 한계 (반드시 함께 기록)

- **val_loss 만으로 판정한다.** 깊이 외삽은 "추론 능력"에 영향을 준다는 주장이 많은데,
  우리는 그걸 측정할 다운스트림 지표가 없다(03 원장의 미도입 항목). **CE 가 안 변해도
  다른 능력이 변할 수 있고, 우리는 그것을 모른다.**
- **R=1.0 이 기존 결과와 정확히 일치함을 먼저 확인**해야 한다. 아니면 구현 버그다.
- 분수 R 의 "어디를 반복하나"가 결과를 바꾸므로 **한 가지 배치만 보고 일반화하지 않는다.**
- 이 실험은 **REVIEW1 의 아키텍처 판정을 바꾸지 않는다.** 후보 A 는 그대로다.
- 개선이 나와도 **추론 비용이 R 배 늘어난다.** 엣지 타깃에서 그게 감당 가능한지는
  P030(추론 속도)이 답해야 한다 → **P030 을 먼저 하는 것이 순서상 맞다.**
