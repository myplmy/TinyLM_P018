# P044 — FiLM 층별 조건화가 **현 후보에서** 이득인가 (목적: 거의 공짜인 품질)

> **신설 2026-08-07.** [P008](P008_점진적타잉-LoRA어닐.md) 에서 **목적별로 분리**했다.
> [P043](P043_어닐LoRA로-KD대체-파이프라인비용.md) 은 **비용**을 묻고, 이 계획은 **품질**을 묻는다.
> **판정 기준이 다르므로 섞지 않는다.**

---

## 1. ★목적 — **0.13MB 로 품질을 살 수 있는가**

FiLM(`--mlp-film`)은 공유 MLP 은닉을 **층별 scale/shift 로 변조**한다: `h·(1+γ)+β`.
파라미터가 `2 × ffn_dim = 4,096` × 중간층 = **약 65K = 0.13MB** 다.

| | 파라미터 | 감축비(g8 기준) |
|---|---|---|
| plain tied g8 | 63.5M | **2.07×** |
| **+ FiLM** | 63.6M | **2.06×** |
| (참고) + 고정 LoRA r32 | 66.7M | 1.94× |

> **★FiLM 은 사실상 공짜다**(감축비 0.5% 손해). **그래서 "이득이 조금만 있어도 채택"** 이
> 성립하는 유일한 조건화 장치다. LoRA 와는 판정 기준이 다르다.

## 2. 왜 지금 다시 보는가 — **현 후보에서 한 번도 안 켜 봤다**

`Layer.__init__` 이 `mlp_film=is_mid_tied` 로 **타이된 층에만** 붙이도록 이미 구현돼 있는데,
**현 후보 `mA`·`mC` 는 `mlp_film=False` 다.** 즉 **한 번도 최종 후보 조합에 들어간 적이 없다.**

### 2.1 구 측정 — 두 조건에서 신호가 다르다

| 조건(300M 풀, g4) | val | 대비 |
|---|---|---|
| `t_base` plain | 3.9558 | — |
| **`t_film`** | **3.9420** | **−0.0138** ⚠️ 분해능 미만 |
| | | |
| `t_kdinit`(KD) | 3.8253 | — |
| `t_all`(KD + LoRA + FiLM) | 3.8188 | **−0.0065** ⚠️ 분해능 미만 |

**둘 다 분해능(0.024) 미만이다.** 평균 비교로는 **판정 불가**다.

> **★그런데 지금은 `paired_eval.py` 가 있다** — SE **0.0005**, σ 의 1/20(결과 021).
> **0.0065~0.0138 급 신호를 볼 수 있는 도구가 생겼다.** 그게 이 계획을 여는 이유다.

### 2.2 ⚠️ 단 `t_all` 은 LoRA 와 FiLM 이 **함께** 켜져 있었다

`t_all` − `t_kdinit` = −0.0065 는 **둘의 합**이다. **FiLM 단독 기여는 미분리**다.
이 계획이 그것을 분리한다.

## 4. ★예측

| # | 예측 | 근거 | 틀리면 |
|---|---|---|---|
| **P1** | **−0.005~−0.015** 정도의 작은 이득 | 구 측정 −0.0138(plain) / −0.0065(KD 포함, LoRA 와 합쳐) | 0 이면 **KD 가 이미 그 자리를 채웠다**는 뜻 |
| **P2** | **분해능(0.024) 미만**이라 `paired_eval` 없이는 못 읽는다 | 구 측정 둘 다 미만 | 0.024 를 넘으면 **즉시 채택** |
| P3 | 메모리 대가는 **0.13MB 로 확인**된다 | 파라미터 산술 | 크면 회계를 다시 본다 |
| P4 | `grad_max` 영향 없음 | FiLM 은 0 초기화라 시작 시 항등 | 커지면 기록 |

> **★P2 를 미리 적어 두는 이유**: 이 실험은 **"작은 이득을 확인하는 것"** 이 목적이지
> "큰 이득을 찾는 것" 이 아니다. −0.01 이 나와도 **성공**이고, 그걸 **0.13MB 와 저울질**하는 것이
> 판정이다. 기대를 크게 잡으면 실제 결과를 실패로 오독한다.

## 5. 단계 설계 — **단순하다. 한 런이면 된다**

### 단계 1 — **현 후보 + FiLM** ⏸ · GPU **약 3.5h**

`mC_wsd`(결과 024) 구성에 **`--mlp-film` 하나만** 더한다:

```
--preset m100R1c --arch tied --data ko-en --tokens 300M --pool-tokens 600M --exact-cache
--steps 2289 --micro-bs 8 --accum 16 --seq 1024 --lr 1e-3
--sched wsd --anneal-end 0.80 --decay-frac 0.2 --seed 1337
--kd --kd-every 4 --init-from --mlp-film --tag mC_film
```

**대조군은 새로 안 돌린다** — `mC_wsd`(3.6442, 결과 024)가 **같은 조건**이다.
⚠️ **그래서 조건 일치가 생명이다.** 로그 헤더에서 `sched=wsd`·`anneal_end=0.80`·
`kd_every=4`·`pool_tokens=600000000` 을 **눈으로 확인**한다.

### 단계 2 — **짝비교** ⏸ · GPU 0 · 수 분

`paired_eval.py --preset m100R1c --models mC_wsd mC_film`.
**SE 0.0005 라 −0.005 급도 t 검정이 된다.**

## 6. 판정 기준

| 결과 | 판정 |
|---|---|
| paired 델타 **< −0.010** 이고 t 유의 | ✅ **채택.** 0.13MB 로 산 이득. `m100R1c` 프리셋에 `mlp_film=True` 승격 검토 |
| **−0.010 ~ 0** | ⚠️ **관측만 기록.** 채택은 보류 — 시드 1개라 방향이 불안정할 수 있다 |
| **≥ 0**(악화) | 🚫 **기각.** FiLM 은 KD 조건에서 무효. 계획 종결 |

**⚠️ `final` 로 읽는다**(결과 015). **⚠️ `grad_max` 는 json 에서.**

> **★분해능(0.024)을 판정선으로 쓰지 않는 이유**: `paired_eval` 은 **eval 샘플링 노이즈를 0**
> 으로 만들고 크롭 단위로 짝지어 뺀다(결과 021). 그래서 SE 가 0.0005 다.
> **단 σ=0.012 는 시드 노이즈이고 그건 여전히 남아 있다** — 그래서 **채택선을 −0.010 으로**
> 잡아 시드 노이즈보다 작은 신호로 결정하지 않는다.

## 8. 한계

- **시드 1개.** paired 가 eval 노이즈를 없애도 **시드 노이즈 σ=0.012 는 남는다.**
  그래서 채택선이 −0.010 이다.
- **g8 하나만.** g4·g16 에서 다를 수 있다(FiLM 은 공유 강도가 셀수록 값어치가 클 것으로 예상되나 미검정).
- 대조군이 **다른 세션에서 학습된 런**이다. 조건은 같지만 **하드웨어 상태는 다르다** —
  품질에는 영향 없지만 **벽시계는 비교하지 않는다.**
- FiLM 파라미터가 **`report()` 에 어떻게 계상되는지** 확인해야 한다
  (결과 026 이 LoRA 에서 정확히 그 문제를 드러냈다) → **단계1 로그의 report 블록에서 확인.**
