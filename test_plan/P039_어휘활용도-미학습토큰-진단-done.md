### 1.1 논문 근거

*Fishing for Magikarp: Automatically Detecting Under-trained Tokens in LLMs*
(Land & Bartolo, Cohere) — [arXiv:2405.05417](https://arxiv.org/abs/2405.05417).
토크나이저가 만든 토큰 중 상당수가 학습 데이터에 거의 안 나오고, 그 임베딩은 초기값 근처에
머물러 **예측 불가능한 행동**을 만든다. 탐지 지표로 **빈도**와 **임베딩 노름**을 쓴다.

우리 조건이 특히 위험해 보였다:

| 조건 | 우리 값 |
|---|---|
| 어휘 | 32,768 |
| 학습 토큰 | 300M → **어휘당 평균 9,155** |
| 토크나이저 학습 표본 | **20만 문서**(코퍼스 전체가 아니다) |

## 4. 방법

`scripts/diag_vocab.py`(2026-08-06 신설, **torch 선택적**):

1. 토크나이저 json 의 vocab 을 읽어 **ByteLevel BPE 를 직접 역매핑**(의존성 최소)
2. `train.bin` 을 `np.bincount` 로 **전량 스캔** → 토큰별 빈도
3. 종류 분류(한글/라틴/숫자/CJK기타/기호)별 배분·빈도0 비율
4. (선택) 체크포인트를 로드해 **임베딩 노름**을 빈도와 교차

**3스캔**: `ko-en_600M`(+`p6d` 노름) / `ko-edu-en_300M` / `ko-edu-en_600M_filtered`

배치: `run_P039_vocab_diag.bat`(GPU 0, 수 분)

### 6.1 ★예측 대조

| # | 예측 | 실제 | 판정 |
|---|---|---|---|
| P1 | 빈도 0 이 1~5% | **0.16%** | 🚫 **빗나갔다.** 예상보다 **한 자릿수 적다** |
| P2 | 미학습 노름이 **작을** 것 | **미사용 0.8315 vs 사용 0.5201 = 비 1.599, 즉 더 크다** | 🚫 **부호가 반대다** |
| P3 | 기호·CJK 에 몰릴 것 | 기호 **7.2%** / CJK기타 1.1% / 본문 0.0% | ✅ **적중** |
| P4 | 필터가 빈도 0 을 늘릴 것 | 36 → 55 (단 **풀 크기도 다르다** = 교락). 희귀 꼬리는 확실히 두꺼워짐(빈도<1000 4.81%→10.33%) | ⚠️ **방향만 적중, 교락** |

### 6.2 ★P2 가 뒤집힌 이유 — 우리 구조 특유

출력 헤드가 임베딩과 **tie** 돼 있어(`logits = F.linear(..., self.emb.weight)`)
**한 번도 정답이 된 적 없는 토큰도 매 스텝 softmax 분모**에 들어간다.
"이 토큰이 아니다" 라는 **일관된 방향의 gradient 만** 받으므로 노름이 **단조 증가**한다.

> **→ Magikarp 의 "노름이 작으면 미학습" 휴리스틱은 untied 헤드를 전제한다.
> 가중치 타잉 모델에서는 그대로 쓰면 정확히 틀린 토큰을 고른다.**
> 표본 53개라 확정은 못 하지만, **타잉 모델 한정의 역방향 지표**로 기록할 값어치가 있다.

### 6.3 판정

| 질문 | 답 |
|---|---|
| Q1 미학습 토큰 | **0.16%** = 53개(대부분 바이트 폴백·특수토큰) |
| **Q2 어휘 축소가 레버인가** | 🚫 **아니다.** 0.16% × 32.0MB = **0.05MB**. **P034 단계5 선택지 (c) 폐기** |
| Q3 종류 | ✅ 기호(7.2%)·CJK기타(1.1%). **본문 토큰은 전부 쓰인다** |
| Q4 필터 부작용 | ⚠️ **희귀 꼬리는 두꺼워졌다.** 단 풀 크기 교락 → 재측정 필요 |

### 6.4 부수 소득

`ko-edu-en` 토크나이저가 어휘의 **62.8%를 한국어**에 배분했다(`ko-en` 은 41.2%).
결과 011 §1.3 의 "영문 8.1% 압축 열세" 가 **미스터리가 아니라 어휘 배분의 직접 결과**임이 확인됐다.
