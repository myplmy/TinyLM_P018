## 1. 왜 — 기존 표가 무언가를 말하는데 그게 신호인지 노이즈인지 모른다

`docs/EXPERIMENT_BASELINES.md` §2.1(같은 300M 풀·300M 학습·plain):

| 태그 | 구성 | 분 | dense 대비 |
|---|---|---|---|
| `dense` | dense | 97.5 | — |
| `t_base` | tied **g4** | 94.9 | −2.7% |
| `t_film` | tied g4 + FiLM | 91.4 | −6.3% |
| `t_g8` | tied **g8** | 89.9 | **−7.8%** |

### 1.1 왜 이 표를 믿을 수 없나

- **같은 g4 인 `t_base`(94.9)와 `t_film`(91.4)이 3.5분 벌어진다 = 노이즈 폭 ±3.7%.**
  게다가 `t_film` 은 **FiLM 연산이 더 있는데 더 빠르다** — 인과가 성립하지 않는다.
- `t_g8` 의 −7.8% 는 그 노이즈의 **2배 남짓**이다. 방향은 믿을 만하지만 **크기는 못 믿는다.**
- **구 로그(2026-07-30 이전)라 `grad_ckpt`·`ema`·`micro_bs`·`accum` 이 기록돼 있지 않다**
  (`CLAUDE.md` 함정 15). **조건이 같았는지 확인할 방법이 없다.**

### 1.2 그리고 이론은 "거의 0" 이라고 말한다

| 스텝 구성요소 | 타잉이 줄이나 | 비중 |
|---|---|---|
| forward GEMM(20층) | 🚫 | 지배적 |
| backward GEMM(20층) | 🚫 | 지배적 |
| grad-ckpt 재forward(20층) | 🚫 | 큼 |
| gradient 누적(공유 텐서에 g번 더하기) | 🚫 (오히려 **추가** 작업) | 작음 |
| **AdamW 스텝** | ✅ 2.09× | **약 0.13%** |

**AdamW 추정**: 132.5M 파라미터 × 약 20B/param(param·grad·m·v 읽고 쓰기) = **2.65GB 트래픽 ≈ 4ms**.
실측 스텝 시간은 `116.6분 × 60,000 ÷ 2289` = **3,057 ms/step** → **0.13%**.

그리고 `report()` 의 FLOPs 식에 `mlp_group` 이 **없다**:

```python
per_l = (dim*dim*2 + kv_dim*dim*2) + 3*dim*ffn_dim
flops = 2 * cfg.n_layers * per_l          # ← 타잉 항이 없다
```

**dense 와 mC 는 토큰당 0.248 GFLOP 로 같다.** 학습 로그 상단에 둘 다 그렇게 찍힌다.

> **★그러므로 −7.8% 가 사실이라면 원인은 파라미터 수가 아니라 다른 것**이고,
> 가장 유력한 후보는 **캐시 지역성**이다 — 추론에서 이미 같은 패턴을 봤다
> (층당 비용 g8 **0.913** < g4 **1.022** < dense **1.163** ms, 결과 014 §11).
> MLP 하나가 fp32 로 **18.0 MiB** 라 L3(32MB)에 들어가고, g8 은 연속 8층이 그걸 재사용한다.

| # | 예측 | 근거 | 틀리면 |
|---|---|---|---|
| **P1** | **2% 미만**(사실상 차이 없음) | AdamW 가 0.13% 뿐. FLOPs 동일 | 5~10% 면 **캐시 지역성이 학습에서도 작동**한다는 신규 관측 |

> **5~10%** → 캐시 귀속. **g 스윕(g4 vs g8 vs g16)으로 단조성을 확인**할 가치가 생긴다.

## 4. 조건 — `--mlp-group` **하나만** 다르다

```
공통: ko-en / --tokens 300M --pool-tokens 600M --exact-cache
      --steps 250 --micro-bs 8 --accum 16 --seq 1024
      --lr 1e-3 --sched cosine --eval-every 999 --compile --seed 1337
      grad-ckpt **ON**(둘 다) · KD 없음 · --init-from 없음 · EMA 없음
```

| 태그 | 차이 |
|---|---|
| `ts_dense` | `--arch dense` |
| `ts_g8` | `--arch tied --mlp-group 8` |

### 4.1 왜 이 조건인가

| 선택 | 이유 |
|---|---|
| **grad-ckpt 를 둘 다 ON** | `--no-ckpt` 는 그 자체로 **−17.3%** 다(결과 007). 한쪽만 켜면 측정하려는 효과를 **완전히 덮는다** |
| **KD 없음** | 교사 forward 가 섞이면 타잉 효과가 희석된다 |
| **250 스텝** | 속도만 보면 충분. **품질은 안 본다** |
| **cosine** | 스케줄은 속도에 무관. 구 표(§1)와 조건을 맞춘다 |
| 같은 배치 안에 두 조건 | 열·부하가 공통으로 걸려 **비율이 살아남는다**(결과 016 §12.5) |

## 5. 측정 위생 (결과 015 → 016 §11 → §12, **같은 계열 3회 재발**)

1. **단독 실행** — 결과 015: 동시 실행이 **+14%**
2. **직전 5분 유휴** — 결과 016 §12: 끝난 토큰화 작업이 **2~9%** 를 먹었다
3. **같은 배치에 두 조건** — 비율로 읽는다

### 5.1 ★`ms/step` 환산은 반드시 한다

로그의 `ms/step` 은 **누적 평균**이고 **torch.compile 첫 스텝(수만 ms)이 섞여 있다.**

```
정상상태 = (누적평균 × N − step0) / (N − 1)
```

250스텝에서 step0 이 6만 ms 면 누적 평균이 **240ms 부풀려진다.** 환산 없이 비교하면 무의미하다.

## 6. 판정 기준

| 조건 | 판정 |
|---|---|
| \|차이\| < 2% | **노이즈.** 기준표 §2.1 정정. "타잉이 학습을 빠르게 한다" 서술 제거 |
| 5~10%, g8 이 빠름 | **실재.** 원인은 **캐시**(파라미터로는 0.13%밖에 설명 못 한다) → g 스윕 후속 |
| 타잉이 느림 | gradient 누적 비용. 기록하고 종결 |

**⚠️ `val_loss` 는 어느 경우에도 읽지 않는다** — 250스텝은 `grad_max` 10~35 불안정 구간이다.
