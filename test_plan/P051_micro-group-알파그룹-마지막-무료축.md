# P051 — `micro_group` 128 → 256: **한 번도 스윕하지 않은 마지막 축**

> **신설 2026-08-07.** 근거 = [결과 028](../test_result/028_20260807_P014C-단계0-per-row는-공짜고-per-tensor는-못쓴다.md)
> 부수 소득 + `202608080900_HANDOFF` §7 열린 질문 *"`micro_group` 스윕 미착수(g256 이 분해능 1/5,
> 단 재학습 필요)"*. **구현 완료 2026-08-07**(`--micro-group`, 미지정 = 프리셋값 = 비트 동일).

## 1. 왜 — 저장 bpw 에 항이 둘인데 하나만 건드려 왔다

우리 저장(packed, 안 B) 회계는 `transformer.py` 가 이렇게 찍는다:

```
B: code(log2 3 / 1.25) + group scale(16 / micro_group)
```

| 항 | g128 에서의 값 | 이 저장소가 한 일 |
|---|---:|---|
| **code** | 1.5850 bpw (log₂3) | P016(3:4 → 1.25) · P034(int8 저장) · P014(패킹) — **여러 번 건드렸다** |
| **group scale** | **0.1250 bpw** (16/128) | ★**한 번도 안 건드렸다** |
| 합 | **1.7100 bpw** | |

`micro_group` 을 **256** 으로 올리면 scale 항이 **0.0625** 로 반이 된다 → **1.6475 bpw (−3.65%)**.
**아키텍처를 하나도 안 바꾸고**(층·깊이·타잉·임베딩 전부 그대로) 저장이 준다.

### 1.1 왜 지금 할 만한가 — 사전 증거가 이미 있다

**결과 028**(P014C 단계0)이 학습된 모델의 α 를 **사후에** g256 으로 재추정해 bpb 를 쟀다:

| 입도 | Δbpb | 우리 실무 분해능(bpb 0.008) 대비 |
|---|---:|---|
| **g256** | **+0.0010 ~ +0.0015** | **1/5 ~ 1/8** |
| per-row | +0.0050 ~ +0.0063 | 0.63~0.79 |
| per-tensor | +0.0465 ~ +0.0862 | **6~11배(못 씀)** |

> ★**그리고 사후 재추정은 상한이다.** g128 로 학습한 가중치를 g256 으로 뭉갠 값이므로,
> **처음부터 g256 으로 학습하면 그보다 나쁠 이유가 없다**(QAT 가 적응한다).
> 결과 028 이 *"g256 은 완전 공짜지만 재학습이 필요하니 무료는 아니다"* 라고 적어 둔 것이
> 정확히 이 실험이다.

### 1.2 다른 레버와의 관계 — **직교한다**

g16 타잉(P045)·prelude/coda(P048)·E 축소(P046)는 전부 **유니크 삼진 파라미터 수**를 줄인다.
`micro_group` 은 **파라미터 수를 하나도 안 줄이고 파라미터당 비트를 줄인다.**
→ **다른 축과 곱해진다.** 결과 032 §8.3 이 발견한 **볼록성(용량을 덜어낼수록 한계비용 상승)의
바깥**에 있다 — 용량을 안 덜어내기 때문이다.

⚠️ **단 상주(runtime)는 안 준다.** 상주는 `유니크삼진 × 4B × 2벌 + 나머지` 라 **bpw 가 식에 없다**
(함정 1). 이 실험은 **packed 전용 레버**다. **인용할 때 반드시 그렇게 쓴다.**

## 4. 선결 구현 — **완료(2026-08-07)**

| # | 무엇 | 어디 | 상태 |
|---|---|---|---|
| 1 | `--micro-group` 플래그 | `cli.py` | ✅ |
| 2 | `cfg.micro_group` 오버라이드 + 불변식 재검사 | `trainer.py`(`--mlp-group` 과 같은 자리) | ✅ |
| 3 | 결과 json 에 `micro_group` 기록 | `trainer.py` | ✅ |

**미지정 = 프리셋값 = 비트 동일**(규약). 검사한 불변식:
`dim % g == 0`(768) · `ffn_dim % g == 0`(2048) · sparse34 면 `g % 4 == 0`.
→ **m100 계열에서 유효한 값은 g ∈ {…, 128, 256}** 뿐이다(768 % 512 ≠ 0 이라 **g512 는 불가**).
**그래서 이 축은 런 하나로 닫힌다.**

⚠️ **KD 교사는 안 바뀐다.** `load_dense()` 가 교사의 **자기 cfg** 로 복원하므로 교사는 g128 그대로다.
**의도된 동작**이다 — 교사를 바꾸면 변수가 둘이 된다.
⚠️ **`--init-from` 은 정상**이다. 이식하는 것은 fp32 latent `weight` 이고 α 는 forward 마다
`micro_group` 으로 다시 계산된다. shape 이 안 바뀌므로 경고도 안 뜬다.

## 5. 단계 설계

### 단계 1 — ✅ **완료·종결 2026-08-07 = [결과 036](../test_result/036_20260807_P051-알파그룹256은-완전히-공짜다-축-종결.md)**

> **paired Δ = −0.0007**(SE 0.0004, **t −1.65**, 승률 52.5%) = *"구분 불가(체크포인트 수준에서도)"*.
> **부호가 오히려 음수**이고 유의하지도 않다. packed **13.050 → 12.578 MB(−3.62%)**, 감축비 **2.15×**,
> **fp32 상주 451.487 → 451.487 로 소수점까지 불변**(P3 적중).
> **예측 4/5 적중** — P1·P2(오차 0.04%)·P3·P5. **P4(`grad_max` 0.5~1.5) 만 빗나감(1.621)**,
> 단 **같은 밤의 `mC_ct`(1.580)도 함께 올라 귀속 불가**(결과 036 §3.1).
> → **G1 통과. 채택. `768 % 512 ≠ 0` 이라 축 종결.**

### 단계 1 (원설계) · GPU 약 3.5h · **무인 실행 가능**

배치 `run_P051_micro_group256.bat`. 대조군 `mC_wsd`(결과 024) **재학습 안 함** —
조건이 `--micro-group` 하나만 다르다.

```
--preset m100R1c --arch tied --data ko-en --tokens 300M --pool-tokens 600M --exact-cache
--steps 2289 --micro-bs 8 --accum 16 --seq 1024 --lr 1e-3 --sched wsd --anneal-end 0.80
--decay-frac 0.2 --seed 1337 --eval-every 100 --compile --kd --kd-every 4 --init-from
--micro-group 256 --tag mC_g256a
```

말미에 `paired_eval.py --models mC_wsd mC_g256a`.

> 태그가 `mC_g256a` 인 이유: `mC_g16` 이 **MLP 타잉 g** 이고 이건 **α 그룹 g** 라
> `mC_g256` 이면 둘이 같은 이름공간처럼 읽힌다. **`a` = alpha.**

### 단계 2 — (조건부) 다른 레버와의 결합 ⏸ 단계1 이 분해능 안일 때만

`m100R1q`(g16 + p1c1) 위에 g256 을 얹으면 packed 9.612 → **약 9.26MB**.
**단 결과 032 §8.3 의 볼록성이 여기에도 적용되는지는 미지**다 — 이 레버는 용량을 안 덜어내므로
적용 안 될 것으로 **예측**하지만, 그것 자체가 단계2 의 질문이다. **배치는 단계1 결과 후에 만든다.**

## 7. 한계

  ★**그런데 대가도 그만큼 작을 것으로 예측**(P1)되고, **직교라 곱해진다**는 것이 이 실험의 값어치다.

  P045 가 `n_middle=16` 때문에 g16 에서 끝난 것과 같은 형태다.
- 결과 028 의 사후 값은 **다른 오차원**이다(α 재추정). 여기서 재는 것은 **재학습**이다.
