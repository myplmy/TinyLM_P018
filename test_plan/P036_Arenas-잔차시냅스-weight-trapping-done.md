## 1. 왜 — 우리가 P016 에서 측정한 것은 논문의 기법이 아니었다

논문(Sherry, arXiv:2601.07892) §3.2 는 이렇게 말한다.

> *"Despite the hardware and bit-utilization advantages of 3:4 structured sparsity, its direct
> application in ternary quantization often triggers significant performance degradation…
> We identify the root cause as **weight trapping**."*

기전은 **gradient homogenization** 이다. 3:4 는 0 이 균일하게 흩어져 있어 희소 행렬이
**dense binary 처럼 행동**하고(Hadamard 변환처럼 신호를 평탄화), 그 결과

```
∂L/∂X = (∂L/∂Y)(Tα)ᵀ        ← 앞 층으로 가는 gradient 가 미분화되지 않는다
```

이 되어 **유효 랭크(ER)가 붕괴**한다(논문 Fig.4: 3:4 는 ER < 750, 이진 양자화와 같은 수준.
gradient 행렬 차원이 4096인데도). 가중치가 이진처럼 양극화되고 삼진의 표현력을 못 쓴다.

**Arenas 는 그 대응책이다** (논문 식 (7)):

```
Y = X·Tα + λ_t·X·W          (T = 삼진 부호, α = 그룹 스케일, W = latent 고정밀 가중치)
∂L/∂X = (∂L/∂Y)(Tα + λ_t·W)ᵀ
```

`λ_t` 는 학습 종료 시점에 **0 으로 어닐**된다 → **추론 오버헤드 0**.

### ★우리 어닐은 Arenas 가 아니다 — 정확히 어디가 다른가

`tinylm/model/ternary.py:TLinear.refresh_quant`:

```python
self._wq = wq + (1.0 - anneal) * (w - wq).detach()
#                                          ^^^^^^^^ ← 여기가 핵심
```

| | 순전파 값 | **역전파 경로** |
|---|---|---|
| **우리 어닐** | `a·wq + (1−a)·w` — FP↔삼진 보간 ✅ | `.detach()` 때문에 **`wq`(STE) 로만** 흐른다 ❌ |
| **Arenas** | `Tα + λ_t·W` — 잔차 **가산** | `(Tα + λ_t W)ᵀ` — **`W` 가 gradient 에 들어간다** ✅ |

**우리는 값 혼합만 하고 gradient 이질성 주입은 하지 않는다.** 그런데 Arenas 의 존재 이유가
바로 **gradient 이질성**이다(논문 §3.2 (1) "Variance Injection and Singularity Breaking").

> **따라서 "Arenas 는 우리 어닐의 특수형"은 순전파 절반만 맞고, 정작 중요한 절반이 틀렸다.**
> 결과 008 의 3:4 품질 비용(+0.035~0.056)은 **논문이 "이렇게 하면 무너진다"고 명시한 조건에서
> 측정된 값**이다.

### 그리고 Arenas 는 3:4 전용이 아니다

논문 §Effectiveness of Arenas (Fig.6 ablation):

> *"we conducted an ablation study across three quantization schemes: binary (1-bit),
> 3:4 structured sparse (1.25-bit), and **pure ternary AbsMean (1.67-bit)**… the integration of
> Arenas yields consistent performance improvements across **all** configurations."*

**즉 우리 비-희소 삼진 모델(`mC_g8_k4`, `p6d`)에도 적용된다.**
이 계획을 sparse34 전용으로 좁히면 안 된다.

## 3. ★예측 — 정직하게

**이득을 기대하는 이유**

- 논문이 **같은 기법·같은 제약**에서 재현 가능한 이득을 보고했고, ablation 이 3개 양자화
  스킴 전부에서 일관됐다.
- 우리 결과 016 §7.3 이 **간접 징후**를 이미 냈다: 3:4 로 학습된 `mA` 의 재구성 오차가
  TWN 대비 **1.285×** 로 세 모델 중 가장 나쁘고(`mC` 1.151 / `p6d` 1.172),
  "TWN 유지 → 3:4 제거" 비율도 **3.34%** 로 가장 높다. **3:4 학습이 가중치 분포를
  나쁜 쪽으로 이동시켰다**는 해석과 부합한다.

**이득이 없을 수 있는 이유 (이쪽이 만만치 않다)**

- **스케일이 9배 다르다.** 논문은 1B/3B·10B 토큰, 우리는 132M·300M 토큰(**파라미터당 2.3 토큰**).
  Undertrained 구간에서는 표현 붕괴 이전에 **데이터가 먼저 병목**일 수 있다.
- **우리 어닐이 순전파 값 혼합은 이미 하고 있다.** trapping 의 일부는 그것으로 이미 완화됐을
  수 있고, 그러면 Arenas 의 증분은 작아진다.
- **효과가 σ=0.012 분해능 아래면 판정 불가**다. 결과 008 의 3:4 비용이 +0.035~0.056 이므로
  그 절반만 회수해도 검출은 되지만, **1/4 만 회수하면 구분 불가**다.
- **학습 비용이 는다.** 논문도 한계 절에 명시("Arenas increases the compute overhead during
  QAT"). 우리 구현은 forward 에 `X·W` GEMM 이 하나 더 붙는다 → **최대 +100% 스텝 시간**
  가능성(§6 에서 상한 계산).

**음성 결과의 가치**: Q3 가 "우리 스케일엔 trapping 이 없다"로 닫히면 **3:4 의 품질 비용은
구조 제약 그 자체**이고, 그건 결과 008·016 의 해석을 확정한다. 그것도 소득이다.

## 4. 단계 설계

### 단계 0 — 구현 가능성 ✅ **확인됨** (논문 §3.2 식 (7)–(8) 확보)

`TLinear.forward` 에 항 하나. `λ_t` 는 trainer 가 스텝마다 내려준다.

```python
# refresh_quant 에서 (개념)
self._arenas_lam = lam        # 스칼라 텐서, compile 안전
# forward 에서
y = F.linear(x, wq)
if self._arenas_lam is not None:                # 학습 중에만
    y = y + self._arenas_lam * F.linear(x, self._w())   # ★detach 없음이 핵심
```

- **`.detach()` 를 붙이면 안 된다** — 그러면 지금 어닐과 같아져서 실험이 무의미해진다.
- 추론에서는 `λ=0` 이므로 **항 자체를 건너뛴다**(오버헤드 0, 논문 §3.2 (3)).
- `--arenas 0.0`(기본 = 끔) 으로 **기존 동작 완전 무변**. `run_smoke.bat` 로 확인.

| 플래그 | 기본 | 의미 |
|---|---|---|
| `--arenas F` | **0.0(끔)** | `λ_0`. 논문은 초기값·감쇠곡선을 스윕했고 warmup 이 도움 |
| `--arenas-end F` | 1.0 | `λ_t` 가 0 이 되는 진행률 |
| `--arenas-warmup F` | 0.0 | 0→`λ_0` 램프 구간(논문 Fig.8: 모든 스케줄에서 이득) |

### 단계 1 — **기전 관측** (GPU 학습 없음, 수 분) ⏸ **먼저 이것부터**

기존 체크포인트 3개로 **weight trapping 이 우리에게 실재하는지** 본다.

## 5. 판정 기준

**σ = 0.012, 분해능 2σ = 0.024.** 판정은 `final`(100 iters) 끼리만(결과 015 §2-(6)).

| 관측 | 판정 | 조치 |
|---|---|---|
| 단계1 에서 `mA` 만 ER·분포가 나쁨 | **trapping 실재** | 단계 2 진행 |

## 8. 한계

- **논문 재현이 아니다.** 스케일(132M vs 1B/3B) · 데이터(ko-en vs Ultra-FineWeb) ·
  토큰(300M vs 10B) · 아키텍처(타잉·CLA)가 전부 다르다. **기전이 우리에게 있는지**만 본다.
- **`λ` 초기값·감쇠곡선을 우리가 모른다.** 논문은 스윕했고 Fig.8 만 공개돼 있다.
  단계 2 는 **한 설정만** 돌리므로, 음성이 나와도 "Arenas 가 무효"가 아니라
  **"이 설정에서 무효"** 다. 이 구분을 결과문서에 반드시 남긴다.
- **표본 1개씩.** 0.024 를 갓 넘으면 재현런 선결.
- 단계 1 의 ER 은 **작은 배치 몇 개**로 추정한다. 논문의 학습 전 구간 추적과 다르다.
- Arenas 는 학습만 바꾸고 **배포 메모리·추론 속도에 영향이 없다**(λ→0). 즉 이 계획은
  **품질 축 전용**이며 P034 의 메모리 결론을 바꾸지 않는다.
