# P038 — 표준 스케줄이 `wsd` 로 바뀌었다: **후보 A·C 를 그 조건에서 다시 한 번** (로드맵 R7)

> 상태: **배치 작성 완료 · 실행 대기** — `run_P038_wsd_recheck.bat`
> 선행: R6(`run_P032_paired_eval.bat`) 을 먼저 돌리는 편이 좋다(설계 근거는 §4).
> ★GPU 실행은 사용자가 한다. AI 는 배치만 만든다(CLAUDE.md 규약).

---

## 1. 왜 — 지금 상태를 한 줄로

REVIEW1(결과 012)은 `mA_g4s34_k4` 와 `mC_g8_k4` 를 **cosine** 스케줄에서 비교했다.
결과 015(P026 단계5)로 **표준 스케줄이 `--sched wsd` 로 개정**됐다.

**급하지 않다.** 상대 비교는 **같은 스케줄이면 성립**하므로 결과 012 의 A vs C 결론은 유효하다.
문제는 앞으로다 — 이후 모든 런이 wsd 인데 후보만 cosine 에 남아 있으면
**향후 모든 비교에 각주가 붙는다.** 이 실험은 그 각주를 없앤다.

## 2. 무엇을 묻나

1. wsd 조건에서도 A 와 C 가 **여전히 구분 불가**인가(결과 012: −0.0183, 분해능 0.024 미만)?
2. 스케줄 교체가 두 후보에 **같은 크기로** 작용하는가, 아니면 한쪽에 유리한가?
   (3:4 는 어닐 구간과 상호작용할 여지가 있다 — P035 가 별도로 다루는 축이다)

## 3. 조건 (변경 금지 — `docs/EXPERIMENT_BASELINES.md` 대조 완료)

| 항목 | 값 | 근거 |
|---|---|---|
| 학습 토큰 | 300M = **2289 steps × mb8 × accum16 × seq1024** | 유효배치 131K. `--accum 16` 누락 시 150M 만 학습됨(005 혼입 사례) |
| 데이터 풀 | `--pool-tokens 600M --exact-cache` | 결과 006: 풀 300M 이면 dense 가 0.12 손해 |
| LR | `1e-3` | 결과 017 확정(accum16 dense grid 권장 정확히 1.0e-3) |
| 스케줄 | `--sched wsd --anneal-end 0.80 --decay-frac 0.2` | 결과 015 개정 표준 |
| 시드 | `1337` | 표준. **여기서 시드를 흔들지 않는다** — 흔들면 스케줄 효과와 섞인다 |
| 아키텍처 | 프리셋 `m100R1a`(g4+3:4) / `m100R1c`(g8) | 핸드오프 §5. KD·부모초기화는 명령줄이 정한다 |
| KD | `--kd --kd-every 4 --init-from` | 정적 k4 = 기본 권장(결과 005) |
| 태그 | `mA_wsd` / `mC_wsd` | `{preset}_{data}_{tokens}_{tag}` 로 네임스페이스 분리 |

**비용**: 두 런 합계 약 **4.3시간**.

## 4. ★예측 — 틀리면 무엇을 배우는가

| 예측 | 근거 | 빗나가면 |
|---|---|---|
| A·C 격차가 **0.024 미만으로 유지** | 결과 012 에서 −0.0183(0.76σ) | 스케줄이 아키텍처와 상호작용한다는 첫 증거 — **P035(어닐 형태)와 합쳐 읽어야 한다** |
| 두 런 모두 cosine 대비 **개선** | 결과 015: wsd 자체 −0.0755(6.3σ) | wsd 이득이 아키텍처 의존적이라는 뜻. 표준 개정 자체를 재검토 |
| `grad_max` 발산 없음 | 실런 3건이 lr 1e-3 에서 0.66~1.33 | LR 재탐색(P001B)의 tied 경고가 실제였다는 뜻 |

## 5. 한계 — **반드시 결과문서에 적는다**

- **각 팔 1시드**다. 따라서 이 실험이 확정하는 것은 **"이 두 런"** 이지 아키텍처가 아니다.
  σ = 0.012, 분해능 0.024 — **그 아래 차이로 서열을 매기지 않는다.**
- `final` 로만 읽는다. `best` 는 eval 추첨의 최소값이라 **하향 편향**이고, 결과 015 에서
  같은 실수로 **판정 부호가 뒤집혔다.**
- 안정성은 인쇄된 `|g|`(10스텝 샘플)가 아니라 json 의 `grad_max` 로 본다.
- 속도는 읽지 않는다 — 다른 작업과 동시 실행이면 **+14% 느려진다**(결과 015 부수 발견).
