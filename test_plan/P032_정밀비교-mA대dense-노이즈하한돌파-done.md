# P032 — mA vs dense 정밀 비교: **val_loss 로는 불가능하다.** 그럼 무엇으로 가능한가

> **✅ 실행 완료 2026-08-01 — 결과: [021](../test_result/021_20260801100000_P032-paired정밀비교-mC가품질도앞선다.md)**
> §2 의 설계가 그대로 작동했다 — **SE 0.0005~0.0007 = σ(0.012)의 1/20**, 재실행 완전 동일(결정성 확인).
> ★**서열: mC 3.7393 ^< mA 3.7543 ^< p6d 3.7608.** mA vs mC = **+0.0150(t=28.1, 크롭 승률 75.9%)**.
> §2.2 의 한계는 **그대로 유효**하다 — 시드 1개이므로 확정 범위는 **'두 체크포인트'이지 아키텍처가 아니다.**

## 질문

결과 012: `mA_g4s34_k4` **3.7003** vs `p6d`(dense) **3.7045** → **-0.0042**.
결과 013: 정성 관찰에서 오히려 **dense 의 반복 붕괴가 더 심해** 보였다(`조선` 21회, `명` 26회 vs mA 8회).

**mA 가 실제로 dense 보다 나은가, 아니면 오차범위인가?**

## ★1. val_loss 로는 확정할 수 없다 — 계산으로 확인했다

σ = 0.0105(결과 012). 두 그룹 각 `n` 런일 때 차이의 표준오차는 `σ√(2/n)`.

| 각 그룹 런 수 | 최소검출차이(95%) | 0.0042 검출? | 총 비용 |
|---|---|---|---|
| 2 (현재) | 0.0206 | ❌ | — |
| 3 | 0.0168 | ❌ | +8h |
| 5 | 0.0130 | ❌ | +16h |
| 10 | 0.0092 | ❌ | +36h |
| **49** | **0.0042** | ✅ | **≈196시간** |

> **0.0042 를 val_loss 로 확정하려면 약 98런 = 196시간이 필요하다. 비현실적이다.**
> 그리고 그 답을 얻어도 얻는 것은 "0.004 만큼 낫다"는 사실뿐이다.

**→ 이 경로는 폐기한다.** 대신 **분산을 줄이는 법**과 **다른 축의 지표**로 간다.

## ★2. 분산을 줄이는 법 — paired 평가 (가장 값싸고 강력)

현재 σ 는 **두 성분의 합**이다:

```
σ² = (학습 재현 노이즈)² + (eval 샘플링 노이즈)²
```

`evaluate()` 는 val 1.5M 토큰에서 **50배치(409,600토큰 = 27%)를 랜덤 오프셋으로 복원추출**한다.
즉 **어떤 크롭을 뽑았는지에 따라 val 이 흔들린다.** 이 성분은 제거할 수 있다.

### 2.1 결정적 full-val (eval 샘플링 노이즈 → **0**)

- val 전체를 **겹치지 않게 순차 순회**: 1.5M / 8,192 ≈ **183 배치**.
- 랜덤 오프셋 대신 `0, seq, 2·seq, …` 로 고정 → **같은 모델은 항상 같은 값**.
- 비용: 수 초. **이것만으로도 σ 가 줄어든다.**

### 2.2 paired per-crop 비교 (크롭 난이도 성분 상쇄)

두 모델을 **같은 183개 크롭**에 통과시켜 크롭별 차이를 본다:

```
Δᵢ = loss_mA(cropᵢ) − loss_dense(cropᵢ)      i = 1..183
보고: mean(Δ), SE(Δ) = std(Δ)/√183, paired t 통계량
```

**핵심**: "이 크롭이 원래 어려운가"는 두 모델에 **공통**이므로 차이에서 사라진다.
독립 평균 비교보다 **훨씬 작은 차이를 검출**할 수 있다.

> **단 한계가 남는다**: paired 비교는 **eval 노이즈만** 없앤다. **학습 재현 노이즈는 그대로**다.
> 즉 "이 두 체크포인트가 다르다"는 확정할 수 있지만,
> "**이 아키텍처가 더 낫다**"는 여전히 여러 시드가 필요하다.
> **이 구분을 결과문서에 반드시 적을 것.**

### 2.3 구현
`scripts/paired_eval.py` (약 60줄, eval 전용):
- 모델 2개 이상 + 캐시를 받아 **동일 크롭 순회**로 per-crop loss 벡터를 만든다.
- `mean(Δ)`, `SE(Δ)`, paired t, **Δ 히스토그램**(어떤 크롭에서 갈리는지)을 출력.
- **검증**: 같은 모델을 두 번 넣으면 `Δ = 0` 이어야 한다(결정성 확인). 이게 통과 못 하면 버그다.

## ★3. 다른 축의 지표 — val_loss 가 못 보는 것

결과 013 의 정성 관찰(dense 가 반복이 더 심함)은 **val_loss 와 독립적인 축**이다.
평균 CE 가 같아도 생성 거동은 다를 수 있다.

### 3.1 반복 붕괴 정량화 ★가장 직접적

013 의 "인상"을 숫자로 바꾼다. 프롬프트를 늘려 **통계로 만든다**.

| 지표 | 정의 | 왜 |
|---|---|---|
| `rep-n` | 생성문에서 반복된 n-gram 비율(n=2,3,4) | 반복 붕괴의 표준 지표 |
| `distinct-n` | 고유 n-gram / 전체 n-gram | 다양성 |
| `max_run` | 같은 토큰 최대 연속 횟수 | `명 명 명…` 같은 극단 사례 |
| `loop_start` | 반복 루프에 빠진 첫 토큰 위치 | 얼마나 버티나 |

- 프롬프트 **30개 이상** × 각 **5회 샘플** × 온도 {0.7, 1.0} → 모델당 300 생성.
- **추론만, GPU 수십 분.** P030 의 KV 캐시가 있으면 훨씬 빠르다.
- **판정**: `rep-3` 등이 두 모델 간 유의하게 다르면 **013 의 인상이 확인**된다.
  이건 val_loss 로는 절대 안 보이는 정보다.

> **주의**: 디코딩 파라미터(top_k·온도)를 고정해야 한다. 반복률은 디코딩에 매우 민감하다.
> 그리고 **반복률이 낮다 = 좋다**는 자동으로 성립하지 않는다(무작위 헛소리도 반복률이 낮다).
> `rep-n` 과 `val_loss` 를 **함께** 봐야 한다.

### 3.2 도메인·구간 분해 — 평균은 같아도 분포가 다를 수 있다

`ko-en` 은 한국어 50% + 영문 50% 다. **평균 CE 가 같으면서 한쪽이 낫고 다른 쪽이 나쁠 수 있다.**

- 크롭을 **한글 토큰 비율**로 층화(≥60% 한글 / ≤40% 한글 / 혼합)하고 각 층에서 paired Δ.
- `scripts/diag_cache.py` 의 한글 토큰 마스크를 재사용하면 구현이 짧다.
- **이게 갈리면 실용적 함의가 크다** — 한국어 타깃이면 한국어 층 성능이 결정적이다.

### 3.3 토큰 위치별 손실
크롭 앞부분(문맥 적음) vs 뒷부분. 압축이 **긴 문맥 활용**을 해쳤는지 본다.
타잉은 깊이를 재사용하므로 장거리 통합이 약해질 수 있다는 가설.

## ★4. 왜 mA 가 dense 보다 나을 수 있는가 — 메커니즘 가설 3개

측정 전에 **그럴듯한 이유가 있는지** 따져야 한다(없으면 노이즈로 보는 게 맞다).

| # | 가설 | 근거 |
|---|---|---|
| 1 | **KD 정칙화** — mA 는 `p6d` 를 교사로 증류했다. 소프트 타깃이 교사의 과적합 성분을 걸러낸다 | 결과 009 에서 이미 관측(ko-edu-en 에서 학생이 교사를 **-0.21** 능가) |
| 2 | **최적화 안정성** — `grad_max` dense **4.31** vs mA **0.66**. dense 가 훨씬 거친 최적화를 했다 | 결과 012 §3.1 |
| 3 | **타잉·희소의 정칙화** — 파라미터가 적고 강제-0 이 있어 정칙화처럼 작동 | 일반론 |

**즉 "mA 가 나을 수 있다"는 메커니즘적으로 그럴듯하다.** 특히 가설 1은 우리가 이미 다른
데이터셋에서 훨씬 큰 규모로 관측한 현상이다. **그래서 측정할 값어치가 있다.**

## ★5. 그런데 — 이 질문에 얼마나 투자할 가치가 있나 (정직한 재평가)

| 우리가 이미 확립한 것 | 상태 |
|---|---|
| "2.64× 압축에 **품질 손실 없음**" | ✅ **확립됨**(결과 012, 0.40σ) |
| "2.64× 압축이 dense 보다 **더 낫다**" | ❓ 미확정 |

**프로젝트 목표는 첫 줄이다.** 두 번째 줄은 자랑거리이지 의사결정에 쓰이지 않는다.
어떤 결론이 나와도 **후보 A 는 그대로 승자**다.

**→ 따라서 §2(paired, 수 분)와 §3.1~3.2(반복률·도메인 분해, 수십 분)만 한다.**
**§1 의 다중 시드 경로(196시간)는 하지 않는다.** 학습을 추가로 돌리지 않는다.

부수 이득이 실제 목적이다:
- **결정적 full-val 은 앞으로 모든 실험의 σ 를 줄인다** — 이게 가장 큰 소득이다.
- **도메인 분해**는 한국어 타깃 관점에서 계속 쓸 지표다.
- **반복률**은 P029 정성 프로브를 정량화해 다음 후보 비교에 재사용된다.

## 판정

| 관측 | 결론 |
|---|---|
| paired Δ 가 0 에서 유의하게 벗어남 | **이 두 체크포인트는 다르다.** 단 아키텍처 우열은 아니다(시드 1개씩) |
| paired Δ 가 0 과 구분 안 됨 | **오차범위 확정.** "동등"으로 기록하고 종결 |
| `rep-n` 이 유의하게 다름 | **013 의 인상 확인.** val_loss 와 독립적인 압축 효과 발견 |
| 도메인 층에서 갈림 | 평균이 숨긴 차이 발견 — 한국어 타깃 관점에서 중요 |

## 비용

- §2 결정적 full-val + paired: 구현 ~60줄, 측정 **수 분**. GPU 최소.
- §3.1 반복률: 구현 ~50줄, 측정 **수십 분**(P030 KV 캐시 있으면 수 분).
- §3.2 도메인 분해: `diag_cache.py` 마스크 재사용, 측정 수 분.
- **학습 0. 총 반나절 미만.**

## 한계

- **paired 는 eval 노이즈만 없앤다.** 학습 노이즈는 시드로만 줄고, 그건 하지 않기로 했다.
  → 결론은 항상 **"이 체크포인트 쌍"** 에 대한 것이며 아키텍처 일반화가 아니다.
- **반복률이 낮다 ≠ 좋다.** 무작위 출력도 반복률이 낮다. val_loss 와 함께 읽어야 한다.
- 도메인 분해의 "한글 비율" 층화는 **토큰 마스크 기반 근사**다(문서 언어 라벨이 아니다).
- 이 실험은 **REVIEW1 판정을 바꾸지 않는다.**

## 우선순위

**§2(결정적 full-val)는 즉시 할 값어치가 있다** — mA 질문과 무관하게 **앞으로의 모든 σ 를 줄인다.**
§3 은 P030(KV 캐시) 이후가 효율적이다(생성이 60배 빨라지므로).
