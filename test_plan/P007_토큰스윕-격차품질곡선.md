# 실험계획 P007 — 토큰 스윕 (100/300/600M) 격차·품질 곡선

## 목적
학습 토큰 예산에 따른 (a) **dense vs tied 격차** 변화, (b) **절대 품질(val loss·bpb)** 곡선을 그려
**수확 체감 지점**과 "300M이 충분한가"를 규명한다. 향후 스케일 실험의 토큰 예산 결정 근거.

## 아키텍처
- `m100` (v5) 고정. 각 토큰 예산마다 **자체 dense 기준선 + tied(g8)** (+ KD-init).

## ★풀 일관성(중요, 방법론 정정)
Loader 는 **캐시 파일 전체에서 매 배치 랜덤 오프셋**을 뽑는다(`loader.py`). 따라서 "300M 캐시에서
100M 소비"와 "600M 캐시에서 100M 소비"는 **표본 풀이 달라 서로 다른 조건**이다(600M 캐시엔 300M
캐시에 없는 뒤쪽 문서가 있고, 균등 샘플링이라 prefix 성질이 등가를 보장하지 못함). 상위호환 재사용
(`_find_reusable`)에 맡기면 100M/300M은 300M 풀에서, 600M만 600M 풀에서 뽑혀 **600M 점이 혼입**된다.

→ **클린판**: 600M 캐시를 먼저 만들고 **모든 예산을 그 600M 풀에서 샘플**한다. 같은 풀+같은 seed면
100M 크롭 ⊂ 300M 크롭 ⊂ 600M 크롭(중첩) → 변수는 오직 "학습한 토큰 수". 구현: 신규 플래그
**`--pool-tokens 600M --exact-cache`**(데이터 풀을 학습길이·이름과 분리, 상위호환 무시하고 정확히 그 크기).
정본 dense 를 덮지 않도록 전 런을 태그(p6d/p6t/p6tk)하고 tied 는 **`--init-from-tag p6d --kd-teacher-tag p6d`**
로 태그된 dense 에서 초기화·증류. **실행: `run100m_P007.bat`(클린판).**

## 실행
**`run100m_P007.bat`(클린판)** 참조 — 600M 캐시 1회 생성 후 100/300/600M 를 모두 600M 풀에서 학습
(태그 p6d/p6t/p6tk), 예산별 `compare --tag p6d --vs p6t|p6tk`. steps = tokens/131072
(100M→763, 300M→2289, 600M→4578). tied 는 g8 고정.

> 참고(구판, 상위호환 재사용 방식 — 600M 점 풀 혼입 있음): `all --tokens 100M` 는 300M 캐시를 재사용해
> 100M 만 학습(로그 "캐시 재사용 300M" 은 정상, 학습토큰=steps×유효배치). 클린판이 이 혼입을 제거한다.

## 측정·판정
- 각 예산에서 **dense val, tied val, 격차, bpb, |g|max** 기록 → 토큰수 대비 플롯.
- 확인점: ① 격차가 토큰↑에서 줄어드는가(undertraining 가설), ② 절대 val의 기울기(수확 체감),
  ③ KD가 각 예산에서 격차를 닫는가(선택: tied에 --init-from --kd 추가 라인).
- **정본 300M 비교선은 불변**(기존 모델 유효). 100/600M은 별도 라인(스케일별 이름으로 공존).

## 비고
- 시간: 100M ≈ 0.5h, 600M ≈ 3h/모델. 600M은 캐시 재토큰화 1회.
- LR 고정(1e-3) — 예산이 커지면 warmup/스케줄 상수는 steps 비례라 자동 조정됨.

### ★계획의 전제 하나가 무너졌다

이 계획서의 §"풀 일관성(중요, 방법론 정정)" 은 **"풀만 다르고 나머지는 같다"** 를 전제로
`--pool-tokens`/`--exact-cache` 를 도입했다. **그 전제가 성립하지 않는다**:

- `prepare()` 의 val 은 **스트림 말미 0.5%** 다 → **풀이 바뀌면 val 셋이 바뀐다**
- 한국어 위키가 약 300M 토큰에서 **고갈**된다(L4) → 풀이 커질수록 **말미가 영어로 채워진다**
- 실측: val 한글 비율 **300M 풀 13.5% / 600M 풀 5.5% / 1200M 풀 0.0%**

> **→ "풀만 바꾸는 실험" 은 현 `prepare()` 로는 설계 불가능하다.**
> **공통 val 을 고정하기 전에는 P007 계열의 풀 비교를 재개하지 않는다.**
> 자세한 것은 결과 006 §5.3~§5.4.
