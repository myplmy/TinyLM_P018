# P023 — Sophia 옵티마이저 검증 (스텝수↓로 벽시계 단축)

> **★차단 해제 2026-08-06.** "P026 통과 후" 로 보류돼 있었는데 **P026 은 결과 015 로 종결**
> (정렬 무효), **P035 로 계열 종결**(형태도 무효)됐다. 자원(steps) 교락 대상이 사라졌다.
> 다만 **HP 재탐색 비용이 크므로 FP8(P022 단계1) 다음**이다. 배치는 구현·설계 확정 후에 만든다.

근거: *Sophia: A Scalable Stochastic Second-order Optimizer for LM Pre-training* (Liu et al.,
arXiv:2305.14342). GPT 125M–1.5B에서 **같은 PPL에 스텝·총연산·벽시계 ~2×↓** 주장 — 우리 100M 스케일에 정확히 해당.

## 왜
학습이 연산바운드라 절대 벽시계를 줄이는 정공법 = **목표 loss까지 스텝(=토큰)↓**. Sophia는
대각 Hessian 추정(Gauss-Newton-Bartlett)으로 곡률을 반영해 AdamW보다 적은 스텝에 수렴 주장.
우리 스케일(125M–1.5B 검증 구간)에 부합해 upside가 가장 큼.

## 핵심 아이디어
- 매 k스텝(예: 10)마다 대각 Hessian 추정 h를 갱신, 업데이트 `θ ← θ - lr·clip(m/max(h,ε), ρ)`.
- clipping이 이질적 곡률·비볼록에서 안정화. per-step 추가비용은 Hessian 추정 1/k로 상각.

## 리스크 / 반론 (선검증 필수)
- **재현성 논쟁**: 후속 벤치(arXiv:2509.01440 등)에서 2× 재현이 데이터·튜닝 의존이라는 보고.
  우리도 **AdamW 동일예산 대비 스텝수 곡선**으로 직접 확인해야(주장 맹신 금지).
- **삼진 STE·어닐 상호작용 미검증**: Hessian 추정이 STE gradient(윈도우 감쇠)와 결합 시 노이즈↑ 가능.
  → 어닐 완료(완전삼진) 구간에서 특히 관찰.
- **HP 튜닝**: ρ(clip), lr, k, β 재탐색 필요. 잘못 튜닝 시 AdamW보다 나쁠 수 있음.
- 우리 `param_groups`(타이드 lr/√g 분리)와 weight_decay 그룹을 Sophia에 그대로 이식해야.

## 구현 방향 (최소 변경)
- `--optim {adamw, sophia}` 플래그. Sophia-G 구현(공식 레포 참조) 또는 검증된 pip 패키지.
- `trainer.py` 의 `torch.optim.AdamW` 분기. param_groups·lr 스케줄(WSD/cosine) 재사용.
- 로그에 optimizer·유효 스텝수 기록.

## 실험 매트릭스 (m100, ko-en, 300M, dense 먼저)
| 태그 | 옵티마이저 | 확인 |
|---|---|---|
| dense (기존) | AdamW | 기준 스텝·벽시계 |
| dense_sophia | Sophia | 같은 val 도달 스텝수·벽시계 비교(목표 <AdamW) |
| (통과 시) t_kd_g8_sophia | Sophia | 타잉+KD+삼진과도 이득 유지되는지 |

## 판정
- **같은 val_loss 도달 토큰수(또는 고정토큰 val)** 로 판정. AdamW 대비 스텝 15%+↓면 채택 후보,
  2× 근접이면 전 실험 기본 옵티마이저 검토. 이득 없으면 음성결과 기록 후 종료.
