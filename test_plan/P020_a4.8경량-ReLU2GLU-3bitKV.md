# P020 — a4.8 경량: ReLU²GLU + 3-bit KV 캐시

근거 논문: *BitNet a4.8: 4-bit Activations for 1-bit LLMs* (Wang·Ma·Wei, arXiv:2411.04965).

## 왜 (범위 한정)
a4.8 전체(4-bit activation + sparsify-then-quantize)는 **추론 가속·대모델 지향**이라 우리 1순위
(메모리)·배포타깃(CPU)과 대부분 어긋난다(activation 저비트는 weight 메모리를 줄이지 않음).
따라서 **저비용·검증가능·우리 목표와 접점 있는 두 조각만** 분리해 실험한다:

1. **ReLU²GLU**: FFN을 `SiLU(gate)*up` → `ReLU(gate)²*up` 로 교체. 논문 Fig.5에서 Swish 대비
   *학습 PPL 소폭 개선* + down-proj 입력 80%+, gate 출력 67.5% 희소(7B 기준). 우리에겐
   (a) 품질 소폭 이득 가능성, (b) 향후 CPU/GPU activation-희소 배포 레버.
2. **3-bit KV 캐시**: post-RoPE absmax 양자화로 K/V를 3-bit. 논문 Table 3에서 3-bit KV가
   평균정확도 거의 무손실. 우리 KV 메모리·롱컨텍스트 배포에 직접 기여(P004 KDA의 KV 목표와
   겹치지만 훨씬 저비용).

> **4-bit activation 양자화는 본 계획에서 제외** — int8×int8/저비트 activation GEMM은 우리
> 소형 모델·CPU 타깃에서 이득이 불확실(별도 검토 §int8 GEMM 보고 참조). 여기선 다루지 않는다.

## 구현 방향 (최소 변경, 플래그 게이트)
- **A. ReLU²GLU** (`config.ffn_act ∈ {silu, relu2}`, 기본 silu):
  `modules.MLP.forward` 의 `h = F.silu(g)*u` 를 `act` 분기. relu2 = `F.relu(g).pow(2)*u`.
  아키텍처 변경이라 **dense 재기준선 필요**(같은 토큰에서 silu vs relu2 비교).
- **B. 3-bit KV** (`config.kv_bits ∈ {16, 3}`, 기본 16; **추론/평가 경로 한정**):
  `Attention.compute_kv` 에서 RoPE 적용 후 K/V를 그룹 absmax로 3-bit 양자화→역양자화(STE 불요,
  추론 시 실제 3-bit 저장은 배포 통합 시). 학습은 16-bit 유지(품질 기준), **eval 시 kv_bits=3
  로 품질 저하폭만 측정**. 저장 포맷 실이득은 배포 단계에서 별도 확인.

## 실험 매트릭스 (m100, ko-en, 300M)
| 태그 | 구성 | 확인 |
|---|---|---|
| dense (기존) | silu, kv16 | 품질 기준 |
| dense_relu2 | relu2, kv16 | 학습 PPL 개선/동급 여부(논문 주장 재현) |
| t_kd_g8 (기존) | silu | 타잉 기준 |
| t_kd_g8_relu2 | relu2 | relu2가 타잉+KD와도 호환·이득 유지되는지 |
| (eval only) t_kd_g8 @kv3 | 학습 kv16, 평가 kv3 | KV 3-bit 품질 저하폭(≤작음 목표) |

## 판정
- ReLU²GLU: dense·tied 모두에서 val 격차 ≤ 노이즈(개선이면 채택). 희소율(참고) 로깅.
- 3-bit KV: eval val 상승폭 작으면(≤+0.02) 배포 옵션으로 채택. KV KB/token 리포트에 3-bit 반영.

## 리스크 / 비고
- relu2는 초기 학습 불안정 가능(제곱 → 큰 활성). 필요 시 gate에 소프트클립 또는 스케일 다운.
- 3-bit KV는 학습이 아니라 배포/추론 이득 — 학습속도와 무관.
- 우선순위: **P016/P019 이후 저순위**. 저비용이라 여력 있을 때 quick win 성격.
