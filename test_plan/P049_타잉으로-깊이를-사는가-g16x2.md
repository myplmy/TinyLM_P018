## 1. 사용자 직관 판정 — **MLP 는 맞고, 총량은 틀리다**

> 사용자: *"g8→g16 으로 MLP 묶음을 늘리면 **g8 1개의 상주메모리와 g16 2개의 상주메모리가
> 비슷할 것**으로 예상"*

**MLP 부분은 정확히 맞다.** MLP 객체 하나의 크기는 **`g` 와 무관**하다 —
`g` 는 *"몇 층이 이 객체를 나눠 쓰는가"* 일 뿐 객체 자체는 항상 `3 × 768 × 2048 = 4.72M` 이다.
따라서 그룹 수가 같으면 MLP 메모리는 **완전히 같다**:

| | 현재 `mC` (m16, g8) | **`g16×2`** (m32, g16) |
|---|---:|---:|
| 중간 그룹 수 | 2 | **2** |
| **유니크 MLP** | **6** | **6** |
| **MLP 삼진** | **28.31M** | **28.31M** ✅ **완전 동일** |

**그런데 총 상주는 비슷하지 않다.** 이유는 하나다:

> ### ★**어텐션은 타잉 대상이 아니다. 층마다 독립이다.**

`g16×2` 는 중간층이 16 → **32** 가 되므로 **깊이가 20 → 36** 이고,
어텐션 파라미터가 **층수에 정비례**한다:

| | `mC` (20층) | **`g16×2`** (36층) | Δ |
|---|---:|---:|---:|
| MLP 삼진 | 28.31M | 28.31M | **0%** |
| **어텐션 삼진** | **26.54M** | **47.78M** | **+80.0%** |
| **총 삼진** | 54.85M | **76.09M** | **+38.7%** |
| packed | 13.05MB | 17.47MB | +33.9% |
| **fp32 상주** | **451.5MB** | **613.7MB** | **+35.9%** |
| int8 상주 | 86.94MB | 108.01MB | +24.2% |
| **어텐션이 삼진에서 차지하는 비중** | **48.4%** | **62.8%** | — |

> **★직관의 절반이 맞았고, 틀린 절반이 더 중요하다.**
> **타잉으로 깊이를 살 수는 있는데 공짜가 아니다** — MLP 는 공짜고 **어텐션 값을 내야 한다.**
> 그리고 **깊어질수록 어텐션 비중이 커져** 이 축의 수익이 체감한다(48.4% → 62.8%).

### 1.1 그래서 진짜 질문은 무엇인가

*"g8×2 와 g16×2 의 메모리가 같은가"* 가 아니라:

> **어텐션 값 +21.2M(+35.9% 상주)을 내고 깊이 20 → 36 을 사면, 품질이 그만큼 좋아지는가.**

**이걸 잰 적이 없다.** 그게 이 계획이다.

## 3. ★예측 — 정직하게

기준선 `mC_wsd`: full-val **3.6984**.

| # | 예측 | 근거 | 틀리면 |
|---|---|---|---|
| **P1** | `g16×2` 가 **`mC_wsd` 를 이긴다**(Δ = **−0.02 ~ −0.08**) | 깊이는 우리가 한 번도 늘려 본 적 없는 축이고, 층 수는 표현력에 직접 기여한다. 어텐션도 +80% 늘어난다 | 못 이기면 **깊이 축이 이 규모에서 포화**했다는 뜻 — 그것도 큰 정보다 |
| **P2** | ⚠️ **그러나 상주 −35.9% 를 정당화하지 못한다** | 결과 032 §8 의 볼록성: 용량을 **더할 때**의 이득은 **뺄 때의 대가보다 작다**(수확 체감). 16.81M 을 빼는 데 +0.0745 였는데 21.2M 을 더해도 −0.0745 만큼은 안 나올 것 | 나오면 **깊이가 파라미터당 가장 효율적인 축**이라는 뜻 → 설계 방향이 바뀐다 |
| **P3** | 학습이 **약 1.8배 느리다** | 36/20 층. 결과 014 §11 의 `a + b×층통과` | 덜 느리면 고정비 `a` 비중이 큰 것 |
| **P4** | `grad_max` 가 **오른다** | 36층은 잔차 사슬이 길다. 결과 032 §2 에서 층 구성 변경이 `grad_max` 를 1.48배 올렸다 | 안 오르면 QK-norm·adaLN 이 잘 잡고 있는 것 |
| **P5** | **부모초기화가 `[init] ★★경고` 4줄을 찍는다** | 학생 36층 vs 교사 20층 → `zip` 이 **20층에서 자른다** = **학생의 뒤 16층이 난수** | ⚠️**이게 P1 을 위협한다** — §4.2 |

> **★P2 를 미리 못 박는 이유**: "더 깊으면 더 좋다" 는 거의 확실히 맞다. 그래서 **P1 이 맞아도
> 채택 근거가 안 된다.** 판정은 **"메모리당 품질"** 로 해야 하고 그 임계를 지금 정한다:
>
> **채택 임계 = Δ가 −0.075 보다 좋을 것**(= 결과 032 §8 이 잰 "16.81M 빼기" 의 대가와 같은 크기를
> 21.2M 더해서 되찾는가). 못 미치면 **깊이는 메모리를 쓰는 가장 나쁜 방법**이다.

## 4. 설계

### 4.1 프리셋 `m100R1d` (신설 필요)

```python
def _m100R1d(seq, ckpt):
    """P049 — 중간 그룹 수는 2개로 고정하고 g 를 8→16 으로 늘려 깊이를 20→36 으로."""
    return dataclasses.replace(_m100R1c(seq, ckpt), n_middle=32, mlp_group=16)
```

`n_middle=32 % mlp_group=16 == 0` ✅ / `cla_group=2`, 36층 짝수 ✅

### 4.2 ⚠️★**부모초기화가 이 실험의 최대 위험이다**

교사 `m100_ko-en_300M_dense.pt` 는 **20층**. 학생은 **36층**.

| 항목 | 동작 |
|---|---|
| `zip(student.layers, teacher.layers)` | **앞 20층만** 이식 → **학생의 뒤 16층 어텐션이 난수** |
| `mid_mlps` | 학생 2그룹 × g16 → `teacher.mid_mlps[j*16+k]`, j∈{0,1}, k∈0..15 → **인덱스 31 요구** → 교사는 16개 → 🚫 **`IndexError`** |

> **★즉 현재 코드로는 `--init-from` 이 죽는다.** 결과 030(E=128)에서 **초기화가 판정을
> 무효로 만든** 전례가 있으므로 **이걸 먼저 해결하지 않으면 실험 자체가 무의미**하다.

**선결 구현 C1 — `init_from_dense` 의 깊이 확장 이식**

교사 층 `i` 를 학생 층 `round(i × nt/ns)` 에 **비례 배치**하고(층 역할 보존),
`mid_mlps` 는 **교사 그룹을 순환 참조**한다:

```python
src = teacher.mid_mlps[min((j*g + k) * t_mid // s_mid, len(teacher.mid_mlps) - 1)]
```

⚠️ **이건 새 기법이고 검증이 필요하다.** 그래서 **단계0 을 게이트로 세운다.**

## 5. 단계 설계

### 단계 0 — **초기화 게이트** ⏸ · GPU 소 · 수 분 · **선결**

`--tiny` 로 학생 깊이 > 교사 깊이 조합을 만들어 `init_from_dense` 가

1. **죽지 않고**
2. **`[init]` 경고를 찍고**
3. **step 0 `ce` 가 `ln(vocab)` 보다 확실히 낮다**(= 이식이 실제로 도움이 됐다)

를 확인한다. **셋 중 하나라도 실패하면 단계1 을 안 한다** — 결과 030 이 그 값을 지불했다.

### 단계 1 — **학습 + paired** ⏸ 단계0 통과 후 · GPU **약 5.8h** · `run_P049_depth_g16x2.bat`

- `--preset m100R1d --kd --init-from --kd-every 4 --sched wsd` — `mC_wsd` 와 동일 조건
- 태그 `mC_d36`
- 판정: `paired_eval.py` vs `mC_wsd`, `mC_g16`, `mC_p1c1g16`

### 단계 2 — **메모리당 품질 곡선** ⏸ 단계1 후 · GPU 0

결과 029·032·033 + 이 런을 한 표에 놓고 **`Δ품질 vs Δ상주`** 를 그린다.
**깊이 축이 다른 레버와 같은 선 위에 있는지**를 본다 —
결과 032 §8 이 밝힌 **볼록성**이 **더하는 방향에서도 성립하는지**가 핵심 질문이다.
