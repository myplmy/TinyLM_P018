## 2. 판정 — **per-row 는 산다, per-tensor 는 죽는다**

### 2.1 per-row: 계획서 게이트 통과

계획서 §판정 기준의 분기는 **`per-row Δbpb < 0.008 → 커널 불필요`** 였다.
관측 최대값이 **+0.0063**(`mC_wsd`)이므로 **네 모델 전부 통과**한다.

⚠️ **단 여유가 크지 않다** — 0.0063 / 0.008 = **79%**. 그리고 아래 §3.2 가 보이듯
**모델이 좋아질수록 이 값이 커진다.** 그래서 판정을 "안전하다" 가 아니라
**"현 시점 후보에서는 통과, 여유 21%"** 로 적는다.

⚠️ **재학습 안 했다** = 이 표는 **비관적 상한**이다. 실제 경로는 per-row 로 재학습(또는
어닐 마지막 구간만 per-row 로 전환)하는 것이므로 대가는 이보다 작을 가능성이 있다.
**그러나 재학습으로 커진다는 시나리오는 없다** — 방향은 확실하다.

### 2.2 per-tensor: **원리적으로 불가에 정량이 붙었다**

실사(분석보고서 §13)는 `quantize_i2_s` 가 텐서 전체에서 `max` 하나를 뽑아
`scale_ptr[0]` 에 넣는 것을 **코드로** 확인하고 U2 를 부정 판정했다.
그때 남은 질문은 *"그래서 실제로 얼마나 나빠지나"* 였다. 답:

> **`mC_wsd` 를 오늘 bitnet.cpp 에 넣으면 0.2610 nats(21.7σ) 를 잃는다.**

이 크기를 우리 실험 이력에 놓으면:

| 비교 대상 | 크기 | 출처 |
|---|---:|---|
| per-tensor 재양자화 대가 | **+0.2610** | 이 문서 |
| 타잉 격차(KD 없음, g8) | +0.15~0.17 | 결과 002·007 |
| KD 가 번 것 | −0.15 급 | 결과 021 |
| **스팸 필터가 번 것** | **−0.296** | 결과 011 §2 |
| 실무 분해능 | 0.024 | 결과 012 |

**우리가 아키텍처로 벌어 온 거의 모든 것과 같은 자릿수를 한 번에 잃는다.**
→ **P014B(외부 구현 재사용)의 중단 권고에 품질 근거가 추가**됐다. 종전 근거는
"빌드가 안 된다"(환경 문제로 읽힐 수 있다)였는데, 이제 **빌드가 됐어도 못 넣는다**.

## 3. 예상 밖 관측 3건

### 3.1 g256 은 완전히 공짜다 (+0.0010~0.0015)

**분해능의 1/5**. α 개수가 정확히 절반이 되는데 대가가 없다.
→ **g128 이 최적이 아닐 수 있다.** 우리는 `micro_group=128` 을 한 번도 스윕하지 않았다
(결과 019 계열에서 α 규약을 건드린 적이 없다). §4 와 합치면 **g256 은 무료 메모리**다.

### 3.2 ★**모델이 좋을수록 per-tensor 에 더 크게 다친다**

| 모델 | g128 bpb(좋은 순) | per-tensor Δbpb |
|---|---:|---:|
| `mC_wsd` | **1.3138** (1위) | **+0.0862** (가장 크게 손해) |
| `mC_g8_k4` | 1.3258 (2위) | +0.0694 |
| `mA_g4s34_k4` | 1.3290 (3위) | +0.0707 |
| `p6d` | 1.3342 (4위) | **+0.0465** (가장 적게 손해) |

`mC_wsd` 와 `mC_g8_k4` 는 **아키텍처가 완전히 같다**(둘 다 g8, m100R1c 계열). 다른 것은
학습(WSD 스케줄)뿐인데 per-tensor 대가가 **+0.0694 → +0.0862 (1.24배)** 로 커졌다.

> **해석: 잘 학습된 모델은 품질의 일부를 α 의 미세 구조에 저장한다.**
> per-row 는 그 구조를 (행 단위로) 남기고, per-tensor 는 지운다.
>
> ⚠️ **이건 가설이다.** 표본 2점이고 α 분포를 직접 보지 않았다. 반증 가능한 형태로 적어 둔다:
> *"per-tensor Δ 는 모델 품질과 양의 상관이고, 원인은 α 텐서의 분산 증가다"* →
> `_alpha` 의 텐서 내 분산을 재면 확인된다(학습 0, 수 분). **미측정.**

### 3.3 dense vs tied: per-tensor 에서만 갈린다

per-row 는 네 모델이 **+0.0050~0.0063** 으로 사실상 같은데, per-tensor 는
dense +0.0465 vs tied +0.069~0.086 으로 **1.5~1.9배** 벌어진다.

⚠️ **교락**: tied 는 텐서 수가 적다(mC 78개 vs p6d 140개). per-tensor 에서 α 총 개수가
**78 vs 140** 이라 tied 쪽이 애초에 더 거칠다. **§3.2 의 학습 효과와 이 텐서 수 효과를
이 데이터로는 분리할 수 없다.** 둘 다 같은 방향으로 작용한다는 것만 말할 수 있다.

### 3.4 `mA` 의 3:4 준정형은 α 규약과 직교한다

`mA`(sparse34)는 4-블록마다 1개를 0 으로 강제하므로 α 재추정의 "비영 위치 평균" 이
다르게 나올 수 있었다. 실제로는 per-row **+0.0050 = `mC` 와 동일**, per-tensor
+0.0707 vs +0.0694 (**1.9% 차이**). → **sparse34 는 이 판정에 영향을 주지 않는다.**
`mA` 를 계속 보존하든 접든 P014C 의 결론은 같다.

## 4. ★부수 소득 — per-row 는 **저장 메모리 레버**다 (안 찾던 것)

이 실험의 목적은 **커널 판정**이었다. 그런데 α 개수가 줄면 **α 를 저장할 비트도 줄어든다.**

우리 삼진 bpw 규약(안 B, `transformer.py:454`) = **코드 + 그룹 스케일**이고,
**`SCALE_BITS = 16.0`(fp16)** 이므로 스케일 항은 **`16/g` bpw** 다.
`b_t = log2(3) + 16/128 = 1.5849625 + 0.125 = 1.7100` — 정본 값이 정확히 재현된다.

| 규약 | 스케일 bpw | 삼진 bpw | Δ vs 1.7100 | mC 의 α 개수 |
|---|---:|---:|---:|---:|
| **g128**(현재) | **0.1250** | **1.7100** | — | 428,544 |
| g256 | 0.0625 | 1.6475 | **−3.7%** | 214,272 |
| **per-row** | `16/I` 가중평균 **0.0186** | **1.6036** | **−6.2%** | **63,744** |

per-row 가중평균: 우리 텐서는 대부분 `I=768`(0.0208)이고 `down_proj` 만 `I=2048`(0.0078) 이다 —
`(9.44M × 0.0078 + 45.42M × 0.0208) / 54.85M = 0.0186`.

packed 총량으로 옮기면(`mem_breakdown` 식을 그대로 계산):

| | 삼진 | 임베딩 | 기타 | **총 packed** | dense 대비 |
|---|---:|---:|---:|---:|---:|
| mC g128 | 11.18 | 1.75 | 0.12 | **13.05MB** | 2.08× |
| **mC per-row** | 10.49 | 1.64 | 0.12 | **12.25MB** | **2.21×** |

> **★per-row 는 "커널을 안 짜도 되는 조건" 이면서 동시에 "저장 −6.1% 레버" 다.**
> 대가는 +0.0050~0.0063 bpb = **분해능 미만**. 구현은 α 재추정 한 번(학습 0).

### ⚠️ 자기 정정 — 처음 이 절을 −13% 로 썼다

첫 계산에서 α 를 **fp32(32비트)** 로 가정했다. 실제 규약은 **fp16(`SCALE_BITS=16.0`)** 이라
스케일 항이 절반이고, 따라서 **이득도 절반**이다: **−13% → −6.2%.**
`transformer.py:456` 을 열어 보지 않고 "스케일이니 fp32 겠지" 로 썼다 — **함정 7(bpw 회계)의
전형**이고, 다행히 정본 1.7100 을 식으로 재현해 보는 과정에서 **1.5849+0.25 = 1.835 ≠ 1.7100**
이 안 맞아서 잡혔다. **규약 값은 항상 코드에서 확인한다.**

⚠️ **상주(runtime) 는 별개다.** 상주는 bpw 와 무관하고 유니크 파라미터 수를 따라간다(함정 1).
int8 경로에서 α 는 `tern × 4/micro_group` 바이트 = mC 에서 **1.71MB / 86.94MB = 2.0%** 뿐이다.
per-row 로 가면 그게 거의 0 이 되어 **상주 −1.9%**.
→ **저장 −6.1% / 상주 −1.9%** 로 **나눠서** 인용할 것.

→ **P014C 단계1 에 이 축을 명시적으로 넣었다**(단계1B).
