WHAT TO RECORD
  1. CPU model, core count, L3 size (from the wmic block above)
  2. tok/s and TTFT per (device, threads, model)
  3. the "speed ratio vs memory ratio" summary the script prints

HOW TO READ IT - the one question that matters
  speed ratio close to the memory ratio  -> memory-to-speed transfer WORKS.
      The whole memory-optimisation thesis gets direct support.
  speed ratio close to 1.0               -> NO transfer at this stage.
      Expected, because weights are dequantised before the GEMM. This is the
      evidence that a packed 5-bit CPU kernel is required to cash in the 1.25bpw.
      Record it as a NEGATIVE RESULT, not a failure.

  Also: if 1-thread CPU tok/s is under about 1, the model is not usable on edge as-is
  and the KV cache (stage 1) becomes the top priority, not an optimisation.

LIMITS: no KV cache yet (absolute values pessimistic, comparisons valid) /
  Windows CPU timing is noisy (median of 3, ignore 1-2 percent) /
  batch 1 single request only - server throughput is a different subject.
