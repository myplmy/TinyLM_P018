## 1.2 σ 추정과 그 한계

- 두 런의 차이 `|Δ| = 0.0119`.
- 표본이 정규분포라면 `E|X₁−X₂| = 2σ/√π = 1.128σ` 이므로 **σ̂ ≈ 0.0119/1.128 = 0.0105**.
- 보수적으로 `σ ≈ 0.012` 로 잡는다.

> **★한계 — 이건 표본 2개짜리 추정이다.** `n=2` 에서 σ 의 신뢰구간은 매우 넓다
> (대략 0.005~0.04 범위를 배제할 수 없다). **"σ 는 0.01 급이지 0.05 급이 아니다"** 라는
> **자릿수 판정**으로만 쓰고, 소수 셋째 자리를 다투는 데 쓰지 않는다.
> 더 좁히려면 런이 더 필요한데(3~5개), **아래 §1.3 결론이 이미 실용적으로 충분**하므로
> 추가 런은 권하지 않는다.

## 1.3 ★결론 — 판정기준을 바꿀 필요가 없다

갱신 규칙은 `임계 = max(0.07, 2σ)` 였다. `2σ ≈ 0.021 < 0.07` 이므로:

> **판정기준 `≤ +0.07` / `+0.07~+0.15` / `> +0.15` 를 그대로 유지한다.**

그리고 그동안 달아온 단서 **"`≤0.05` 급 차이를 단정하지 말 것"은 과했다.**
실무 분해능은 **`2|Δ| ≈ 0.024`** 수준이다:

| 차이 크기 | 판정 |
|---|---|
| `< 0.024` (≈2σ) | **구분 불가** — "차이 없음"으로 취급 |
| `0.024 ~ 0.07` | 실재하는 차이지만 **판정기준상 성립 범위** |
| `> 0.07` | 성립 실패 |

| **본 결과 (600M 풀)** | g8 + init + **k4** | **-0.0183** |

**→ 공정 풀에서도 tied+KD(k4)가 dense 를 능가한다(-0.0183, 1.74σ).**

즉 결과 005 의 헤드라인("tied+KD 가 dense 를 능가")은 **풀 아티팩트가 아니었다.**
1차 리뷰 §0-5 와 §5-B 의 "병기, 확인런 대기" 상태를 **해제하고 005 를 유효로 확정**한다.

**단 크기는 줄었다**: 300M 풀에서 -0.0366 → 600M 풀에서 -0.0183. **절반으로 감소.**
결과 006 §2-(1)의 논리("풀 결핍은 dense 를 더 해친다")와 정확히 부합한다 —
dense 가 공정 풀에서 강해지자 KD 의 상대적 우위가 줄었다. **방향은 유지, 크기는 축소.**

결과 006 의 `p6tk`(+0.0616)와 `mC`(-0.0183)의 차이 **0.0799** 는 두 요인의 합이다:
`full KD → k4` 전환(결과 005 기준 0.0417) + 나머지 0.038(3.6σ). 나머지는 `--ema 0.999` 유무와
잔여 노이즈로 보이나 **분리 측정하지 않았으므로 단정하지 않는다.**

## 3.5 ★희소의 순수 비용이 공정 풀에서 재확인됐다

`mC`(g8) → `mB`(g8+s34) 는 **g 고정, 희소만 켠** 비교다.

| 풀 | 비교 | 희소 단독 비용 | 메모리 이득 |
|---|---|---|---|
| 300M(결과 008) | `t_kd_g8` → `t_kd_g8_s34` | **+0.0555** | 14.9 → 10.3MB (1.45×) |
| **600M(본 결과)** | `mC_g8_k4` → `mB_g8s34_k4` | **+0.0433** (4.12σ) | 14.9 → 10.3MB (1.45×) |

**+0.04~0.056 으로 재현.** 공정 풀에서 약간 작아졌지만 같은 급이고, **4.12σ 로 확실히 실재**한다.

## 3.6 ★"타잉과 희소는 초선형 경합" — 공정 풀에서 강하게 재확인

결과 008 §2-(3)의 핵심 발견을 독립 조건에서 다시 측정했다.

| 조건 | g4 → g8 비용 |
|---|---|
| **희소 없음** (결과 008: `t_kdinit` 3.8253 → `t_kd_g8` 3.8292) | **+0.0039** (거의 0) |
| **희소 있음** (본 결과: `mA` 3.7003 → `mB` 3.7295) | **+0.0292** (2.78σ) |

**희소가 있으면 g4→g8 의 비용이 7.5배 커진다.** 두 레버가 같은 자원(용량)을 먹는다는
결과 008 의 해석이 공정 풀에서 재현됐고, **그래서 B 가 탈락했다.**

→ **설계 규칙 확정: 타잉과 희소를 동시에 최대로 밀지 않는다. 희소를 쓰면 g 는 4 에서 멈춘다.**

## 3.7 부수 관찰

- **`grad_max` 0.66~1.03** — 전부 안정. dense(4.31)보다 훨씬 낮다.

# 4. ★학습 곡선 해석 — "loss 2↔4 진동"과 "val-train +1.6"은 **보고 방식의 문제**였다

사용자 질문: *"loss 가 2와 4 사이를 왔다갔다 하고, val-train 이 중간엔 0 근처였다가 마지막에
+1.6 까지 늘어난다. 정상인가? 하이퍼파라미터나 방법론이 잘못된 건가?"*

**결론: 학습은 정상이다. 두 현상 모두 `--kd-every 4` 와 로그 코드의 상호작용이다.**

## 4.1 "loss 2↔4 진동" = KD 스텝 vs 비KD 스텝

`trainer.py` 는 KD 스텝에서 **혼합손실**을 최적화한다:

```
KD 스텝    : loss = (1-α)·CE + α·KL·T²      (α=0.5, T=2.0)
비KD 스텝  : loss = CE
```

`--kd-every 4` 면 `s % 4 == 0` 인 스텝만 교사 forward 를 한다. 인쇄되는 `loss` 는 **그 스텝에서
실제로 최적화한 값**이므로 4스텝 주기로 값이 뛴다. 결과 007 로그에서 10스텝마다 인쇄된 값을
`s mod 4` 로 분류하면 완벽히 갈린다:

| `s mod 4` | KD? | 인쇄된 loss |
|---|---|---|
| 0 | ✅ 교사 forward | 2.34 ~ 3.27 |
| 2 | ❌ 순수 CE | 4.09 ~ 4.81 |

**KL 항이 CE 보다 작기 때문에**(학생이 교사에 가까움) 혼합손실이 더 낮게 나온다.
**진동이 아니라 두 다른 양을 번갈아 인쇄한 것이다.** 학습 불안정과 무관하다(`grad_max` 0.66~1.03).

## 4.2 "val-train 이 마지막에 +1.694" = 최종 eval 만 KD 스텝에 걸렸다

eval 트리거는 `if (s+1) % eval_every == 0 or s == steps-1` 이다. `eval_every=100`, `steps=2289`:

| eval 시점 | `s` | `s mod 4` | train 에 인쇄되는 값 | val-train |
|---|---|---|---|---|
| 주기 eval (100, 200, …, 2200) | 99, 199, …, 2199 | **3** (항상) | 순수 CE ~3.7 | **≈ 0** ✅ |
| **최종 eval** | **2288** | **0** | **혼합손실 2.083** | **+1.694** ❌ |

`100k − 1 ≡ 3 (mod 4)` 이므로 **모든 주기 eval 은 비KD 스텝**에 걸리고, `2288 = 4×572` 라
**최종 eval 만 KD 스텝**에 걸린다. 그래서 마지막 한 점만 튄다.

**즉 `val-train +1.694` 는 과적합이 아니라 단위가 다른 두 수를 뺀 값이다.**
같은 현상이 결과 008(full KD, 매 스텝 혼합)에서는 **전 구간** 나타났다(`val-train +1.7~2.9`).

## 4.3 ★진짜 학습 상태 — 주기 eval 을 보면 명확하다

`mA` 의 주기 eval(전부 비KD 스텝 = 순수 CE 비교):

| 스텝 | 200 | 600 | 1000 | 1400 | 1800 | 2200 |
|---|---|---|---|---|---|---|
| val | 5.19 | 4.72 | 4.14 | 3.84 | 3.77 | 3.75 |
| train(CE) | 4.16 | 3.88 | 3.82 | 3.82 | 3.80 | 3.65 |
| **val−CE** | +1.03 | +0.83 | +0.33 | **+0.02** | **-0.03** | **+0.10** |

**초반에 val−train 이 +1.0 이었다가 중반 이후 0 근처로 수렴한다.**
이건 **과적합의 반대** — 초반엔 val 이 나쁘고(모델이 아직 못 배움), 학습이 진행되며 둘이 만난다.
최종적으로 **val ≈ train** 이므로 **과적합이 전혀 없다. 순수하게 underfit 상태다.**

(초반 +1.0 의 이유: train 은 부모초기화된 가중치로 시작해 첫 스텝부터 낮고, val 은 완전 삼진
`anneal=1.0` 상태로 평가된다. 어닐이 진행되며 둘의 조건이 수렴한다.)

## 4.4 하이퍼파라미터·방법론 진단 — **잘못된 것은 없다. 단 LR 재탐색은 값어치가 있다**

| 점검 | 관측 | 판정 |
|---|---|---|
| 과적합? | val ≈ train (§4.3) | ❌ 없음 → 정칙화 추가 불필요 |
| LR 너무 높음? | `grad_max` 0.66~1.03, `skip 0`, 단조 감소 | ❌ 아님 → 발산 징후 없음 |
| 스케줄 문제? | val 이 매끄럽게 단조 감소, 정체 구간 없음 | ❌ 아님 |
| 학습효율 낮음? | **underfit** — 토큰이 부족한 것이지 방법이 틀린 게 아니다 | ⚠️ 데이터 예산 문제 |
| **LR 너무 낮음?** | 안정적이고 underfit 이면 **더 높은 LR 이 가능**할 수 있다 | ⚠️ **미검증** |

**핵심 진단**: 우리는 **파라미터당 2.3 토큰**(Chinchilla 권장의 1/9)이다. val≈train 은
"데이터를 다 못 짜냈다"가 아니라 **"데이터가 부족하다"**는 뜻이다. 결과 006 이 이미 측정했듯
300M→600M 에서 -0.18 이 더 나온다. **효율 문제가 아니라 예산 문제다.**

**단 하나 열린 의심이 있다.** `lr 1e-3` 은 **v5 시절 발산을 잡느라 낮춘 값**이다
(v4 에서 2e-3 이 발산). 그 뒤 **QK-norm + NaM 가드 + 삼진 어닐이 들어와 안정성이 크게 개선**됐고,
지금 `grad_max` 는 1 근처다. **즉 LR 상향 여유가 있을 가능성이 있고, 한 번도 재확인하지 않았다.**

→ **권고: `lrfind` 재실행**(이미 구현돼 있음, 150스텝 range test = 수 분).
`1.5e-3`·`2e-3` 이 안정하면 같은 예산에서 더 내려갈 수 있다. **가장 값싼 미검증 레버.**

## 4.5 부수 발견 — eval 표본 크기가 `best` 와 `final` 을 어긋나게 한다

- 주기 eval = `evaluate(model, va, **50**, device)` (50 배치)
- 최종 eval = `evaluate(model, va, **100**, device)` (100 배치)

50배치 = 409,600 토큰 / val 1.5M 토큰의 **27%**(랜덤 오프셋, 복원추출).
그래서 **`best`(50배치 중 최저)와 `final`(100배치)은 서로 다른 측정**이며,
`best > final` 인 경우가 정상적으로 발생한다(A·B·C·`p6d` 전부 그렇다).

**→ `best` 와 `final` 을 섞어 비교하지 말 것.** 그리고 val 전체를 결정적으로 훑으면
(1.5M / 8,192 ≈ 183 배치) eval 노이즈가 사라져 **σ 가 더 줄어든다** — 비용은 수 초.
후속 개선 후보(§5-3).

## 4.6 조치 (구현 완료)

`trainer.py` 를 고쳐 **혼합손실과 순수 CE 를 분리 기록**한다:

- 매 micro-batch 에서 `ce` 를 **KD 여부와 무관하게** 누적(`tot_ce`).
- eval 줄: `(train_ce 3.650, val-CE +0.100, 혼합손실 2.083[KD스텝])` — 단위가 섞이지 않는다.
- 스텝 줄: `loss 2.0834*  ce 3.6512` — `*` 가 KD 스텝 표시. **2↔4 진동의 정체가 로그에서 즉시 보인다.**
- json `hist` 에 `train_ce`·`kd_step` 기록, `gap` 은 **CE 기준**으로 계산.
