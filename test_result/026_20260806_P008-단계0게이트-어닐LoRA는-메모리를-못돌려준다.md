# 026 — P008 단계0 게이트 : **어닐 LoRA 는 메모리를 안 돌려준다.** 6시간을 수 분에 살렸다

- **계획**: [P008](../test_plan/P008_점진적타잉-LoRA어닐.md) §7 단계0
- **로그**: `smoketest_logs/log_20260806_P008-stage0.txt` (스모크라 `test_result/` 가 아니다)
- **배치**: `run_P008_stage0_gate-done.bat`   - **비용**: 수 분, tiny 프리셋

## 0. 한 줄 결론

> **게이트 실패.** `s(t) → 0` 으로 어닐해도 **`report()` 가 LoRA 를 그대로 계산에 넣는다** —
> 저장 **1.0 vs 0.9 MB**, 상주 **29.1 vs 26.8 MB**.
> **P008 의 핵심 주장("어닐 LoRA 는 배포 메모리 대가가 0")이 구현 상태로는 거짓**이다.
> **단계1(6 GPU시간)을 돌리기 전에 잡았다** — 게이트의 존재 이유가 정확히 이것이다.

## 1. 측정 결과

동일 조건(tiny / synthetic 2M / 30 steps / g2), **다른 것은 LoRA 하나**:

| 항목 | [1/2] `--lora-rank 32 --lora-decay 0.5` | [2/2] LoRA 없음 | 차이 |
|---|---|---|---|
| 삼진 가중치 | 2.5M / 0.5MB | 2.5M / 0.5MB | — |
| **LoRA(r=32, 2bit)** | **0.3M / 0.1MB** | **없음** | **+0.3M** |
| 임베딩 | 2.1M / 0.4MB | 2.1M / 0.4MB | — |
| **합계 파라미터** | **4.9M** | **4.6M** | **+0.3M (+6.5%)** |
| **저장(packed, 안 B)** | **1.0 MB** | **0.9 MB** | **+11%** |
| **★상주(runtime)** | **29.1 MB** | **26.8 MB** | **+2.3MB (+8.6%)** |

⚠️ **손실은 읽지 않았다** — tiny·synthetic 30스텝은 순수 암기 벤치이고 품질 신호가 아니다.

## 2. ★왜 이렇게 되나 — 예측했던 그대로

계획 P008 §7 단계0 이 미리 적어 둔 경고:

> ⚠️ **주의 — 체크포인트에는 LoRA 파라미터가 남는다.** s=0 이면 **계산에 기여하지 않지만**
> `state_dict` 에는 들어 있다. `mem_breakdown()` 이 `lora` 항을 세므로
> **감축비가 s=0 인데도 1.71× 로 보일 수 있다.**

**정확히 그렇게 됐다.**

- `LoRA._scale = 0` 은 **forward 의 기여**를 0 으로 만든다 ✅
- 그러나 `nn.Parameter` 인 `D`·`U` 는 **여전히 존재**한다
- `mem_breakdown()` 은 `isinstance(m, LoRA)` 로 파라미터를 세므로 **그대로 계상**한다

> **★"계산에 기여하지 않는다" 와 "메모리에 없다" 는 다른 말이다.**
> 이 프로젝트가 반복해 만난 구분(저장 ≠ 상주, 파서에 있다 ≠ 전달된다)의 **또 하나의 사례**다.

## 3. 판정

| 게이트 | 조건 | 결과 |
|---|---|---|
| **G0** s=0 의 메모리 회계 | 저장·상주가 LoRA 없음과 **일치** | 🚫 **실패**(+11% / +8.6%) |
| 학습 안정성 | 30스텝 완주, NaN 없음 | ✅ 통과(부수) |
| `--lora-decay` 배선 | CLI → trainer → `set_lora_scale` | ✅ 통과 |

**→ 단계1(6 GPU시간)은 이 상태로 돌리지 않는다.**
돌렸다면 **존재하지 않는 이득에 붙은 품질 숫자**를 얻었을 것이다.

## 4. ★조치 — 계획서가 제시한 두 안 중 (a)

| 안 | 내용 | 판정 |
|---|---|---|
| **(a) 배포 내보내기 경로** | 학습 후 `lora_rank=0` 으로 재로드해 LoRA 를 **실제로 떨어뜨린다** | ✅ **채택.** 정직하다 |
| (b) `mem_breakdown` 이 s=0 이면 LoRA 를 건너뛴다 | 회계만 고친다 | 🚫 **거짓말이다** — 내보내기가 실제로 지우지 않는 한 |

배치 꼬리말이 미리 *"(a) 를 고르고 게이트를 다시 돌려라"* 라고 적어 둔 그대로다.

**필요한 구현**(소):

1. `scripts/export_deploy.py`(신설) — 체크포인트에서 `lora_*` 키를 **제거**하고
   `cfg.mlp_lora_rank = 0` 으로 저장. **로짓 동등성 게이트 포함**(s=0 이면 출력이 같아야 한다)
2. 게이트 재실행 → 저장·상주가 LoRA 없음과 **일치**해야 통과

⚠️ **로짓 동등성이 `0.000e+00` 이 아닐 수 있다** — 마지막 스텝의 s 가 정확히 0 인지
스케줄 경계에 달렸다. `lora_decay=0.5` 면 진행률 0.5 이후 0 이므로 **끝에서는 0 이 맞다.**
**확인 후 인용한다.**

## 5. 후속

1. **[필수] `export_deploy.py` 구현 + 게이트 재실행** — 단계1 의 선결. GPU 0, 수 분
2. **[중] 같은 문제를 FiLM 도 갖는가** — FiLM 은 **어닐하지 않고 끝까지 남기는** 설계라
   해당 없다. 다만 0.13MB 를 **계상하고 있는지**는 확인 가치 있음
3. **[해당 없음] 단계1** — 1번 전에는 돌리지 않는다

## 7. 한계

- **tiny 프리셋**이라 절대 MB 는 의미 없다. **두 런의 비교만** 유효하다.
