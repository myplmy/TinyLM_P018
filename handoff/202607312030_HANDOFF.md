### 8.1 ★(1) 진단 정정 — 앞선 §1-1 은 **다른 문제**를 고친 것이었다

사용자가 말한 "배치 출력 ≠ 로그" 는 **콘솔 화면과 `test_result/log_*.txt` 의 내용 차이**였는데,
앞 세션의 AI 는 이를 "두 스크립트가 서로 다른 MB 를 찍는다"로 **잘못 읽었다.**
(그 MB 하드코딩은 **실재하는 별개 결함**이고 수정도 유효하다 — 결과 014 §10.7. 다만 (1)의 답은 아니다.)

**진짜 원인**: `runlog.py` 는 **감싼 파이썬 명령의 출력만** 기록한다. 배치의 `echo` 로 나오는
**단계 제목·판정 안내·WHAT TO RECORD 블록이 로그파일에 전혀 안 들어간다.** 콘솔에는 있고
파일에는 없으니 다를 수밖에 없었다. 사용자가 계속 콘솔을 복사해 붙여 온 이유가 이것이다.

**수정 3건**
1. `runlog.py --note "제목"`(여러 개면 여러 줄) — 명령 없이 텍스트만 콘솔·파일에 **동시** 기록.
   전 배치 28개의 `[N/M]`·`[run]`·`[pre]`·`[guard]` 표지에 자동 삽입(실제 명령 **앞**이라 errorlevel 무영향).
2. 줄끝을 `os.linesep` 으로 — 종전 `newline=""` 라 파일이 **LF 전용**이었다(메모장에서 한 줄로 붙음).
3. **기록 후 검증** — 파일 존재·크기를 확인해 함께 찍고, 없거나 0바이트면 **경고**한다.
   종전 꼬리말은 파일 유무와 무관하게 경로만 찍었다.

> **`log_*.txt` 가 하나도 없던 이유 = 사용자 수동 정리**(2026-07-31 확인). 결과문서를 쓸 때
> 번호를 붙여 rename 하거나, 실패한 런의 로그를 지운 것이다. **문제 아님.**
> 3번(기록 후 검증)은 그것과 별개로 남긴다 — 앞으로는 꼬리말이 `(12,345 bytes)` 처럼
> **크기까지** 찍으므로, 경로만 찍히고 실제로는 없는 상황이 생기면 그 자리에서 드러난다.

### 8.5 ★P031 단계0 구현 (신규)

| 파일 | 변경 |
|---|---|
| `config.py` | `infer_repeat: float = 1.0` · `repeat_where: str = "front"` · `repeat_kv_reuse: bool = False` + `__post_init__` 검증 |
| `model/transformer.py` | **`visit_schedule()`** 신설 · `forward()` 가 `enumerate(self.layers)` 대신 스케줄을 돈다 · 캐시 키를 통과번호로 분리 |
| `cli.py` | `--infer-repeat` · `--repeat-where` · `--repeat-kv-reuse`, `eval` 경로에서 cfg 덮어쓰기 + 스케줄 요약 출력 |

**정의**(계획 P031): 공유되는 것은 MLP 가중치뿐이고 어텐션·norm 은 층마다 따로 있으므로
"추론 시 g 를 늘린다"는 성립하지 않는다. 성립하는 유일한 정의는 **middle 블록을 R 회 통과**.
`total = round(n_middle × R)`, prelude·coda 는 건드리지 않는다.

**안전장치 3가지**
1. **R=1.0 이면 스케줄 == `range(n_layers)`** → 종전 경로 비트 동일. 캐시 키도 그때만 정수
   owner 인덱스를 그대로 쓴다(반복 중일 때만 `(owner, 통과번호)`). 안 그러면 두 번째 통과가
   첫 통과의 KV 를 **조용히 덮어쓴다**.
2. **학습에서 켜면 예외.** 층 반복은 학습된 깊이 분포 밖이고 grad checkpoint 와도 섞인다.
3. 축소(R^<1)에서 CLA 그룹 경계가 잘려 owner 가 스케줄에 없으면 **그 층이 스스로 KV 를 계산**한다
   (조용한 `KeyError` 대신 명시적 폴백).

**검증 완료**: R∈{0.5,0.75,1.0,1.25,1.5,2.0} × where∈{front,back,even} **18조합 전부**
계획서 §표의 통과 횟수(12/16/20/24/28/36)와 일치. R=1.0 이 `range(20)` 과 동일함도 확인.

### 8.4 (4) `torch.quantile` 크래시 — **수정 완료, 재실험 필요**

- **원인**: `torch.quantile` 은 입력 **2²⁴(16,777,216)** 초과에서 `RuntimeError` 를 낸다.
  `weight_stats()` 가 TLinear **층당 20만 표본**을 모으는데, dense(`p6d`)는 타잉이 없어
  TLinear 수가 많아 **약 30M** 이 됐다. 타잉 모델은 층이 적어 통과 → **dense 만 골라서 죽었다.**
- **수정**: `torch.cat` 이후 **8M 로 한 번 더 표본추출**(층별 표본을 이미 뽑았으므로 분위 추정 불변).
  덧붙여 `randperm` 을 텐서와 같은 디바이스에서 생성하도록 고쳤다.
- **재실험 필요 = 예**. 크래시한 것이 **혼란요인 제거용 dense 대조군**이라, 남은 두 모델
  (g4+3:4 vs g8)은 3:4 와 g 가 함께 움직여 **귀속이 불가능**하다. 결과 019 는 "판정 불가"로 기록했다.
  → **`run_P036_stage1b_trapping.bat`** (GPU 초 단위). 여기서 R5(4.5h) 가부가 갈린다.

### 9.2 P036 단계0 — Arenas 구현

```
Y = X·Tα + λ_t·X·W            (논문 식 7)
∂L/∂X = (∂L/∂Y)(Tα + λ_t·W)ᵀ  (식 8)  ← latent W 가 **입력 gradient 경로**에 들어간다
```

| 파일 | 변경 |
|---|---|
| `config.py` | `arenas: bool = False` · `arena_lambda: float = 0.1`(λ₀) · `arena_end: float = 0.9` |
| `model/ternary.py` | `refresh_quant(anneal, arena=None)` — `arena` 가 있으면 `self._wq += arena * w` 를 **detach 없이** |
| `model/transformer.py` | `_arena` 버퍼 + `set_arena()`, `refresh_quant()` 가 λ_t^>0 일 때만 전달 |
| `train/trainer.py` | λ_t 를 λ₀→0 으로 선형 감쇠, `arena_end` 이후 0 고정. json 에 3필드 기록 |
| `cli.py` | `--arenas` · `--arena-lambda` · `--arena-end` |

**왜 별도 항인가**: 우리 어닐은 `wq + (1−a)(w−wq).detach()` 라 `.detach()` 때문에
**latent W 가 gradient 경로에 없다**(결과 016 §8.6). Arenas 의 존재 이유가 정확히 그 경로다.
**두 항은 다른 일을 한다** — 하나로 합칠 수 없다.

**추론 오버헤드 0**: λ_t 가 `arena_end`(기본 진행률 0.9)에서 정확히 0 이 되므로 배포 시점의
가중치는 **순수 삼진**이다. `arenas=False` 면 `arena=None` 이 전달돼 **기존 경로와 비트 동일**.

⚠️ **구현했다고 돌리라는 뜻이 아니다.** 단계2 는 4.5 GPU 시간이고, **단계1B 가 우리 스케일에서
