## 4. 사용자 성향 (이번 세션 강화)

- **"오차범위인지 실제인지 확인할 방법"** 을 묻는다 → **통계적 검출력을 계산해 보여주는 것**이
  올바른 응답이었다(0.0042 확정에 98런/196h 필요 → 경로 폐기). **막연한 "노이즈일 수 있다"는 부족.**
- **학습 곡선의 이상 징후를 정확히 짚어낸다.** "loss 2↔4, val-train +1.6" 질문이 **실제 보고 결함**을
  찾아냈다. 사용자 관측을 **의심하지 말고 끝까지 추적**할 것.
- **윤곽/상세를 구분해 요청**한다("아직 실험 안 끝났으니 윤곽만"). 과도한 상세화는 원하지 않는다.
- 배치파일은 **실행 가능 여부를 명확히** 해야 한다(P031 은 구현 선결 → 가드로 처리).
- 삭제 가능 여부를 매 턴 묻는다 — **완료/재사용 가치를 구분해 답할 것.**

### ★함정 (새로 판명)

1. **KD 스텝의 인쇄 `loss` 는 혼합손실**(α·CE+(1-α)·KL·T²)이다. `--kd-every 4` 면
   `s%4==0` 만 KD → **인쇄 loss 가 2↔4 로 교대**한다. 진동이 아니다.
2. **주기 eval 은 `s≡3 (mod 4)` = 비KD, 최종 eval 은 `s=2288≡0` = KD 스텝**에 걸린다.
   그래서 **마지막 val-train 만 +1.694 로 튀었다.** 과적합이 아니다. → **수정됨**(CE 분리 보고).
3. **주기 eval = 50배치, 최종 eval = 100배치.** 서로 다른 측정이라 **`best > final` 이 정상**이다.
   **섞어 비교하지 말 것.** val 전체 결정적 순회(183배치)로 바꾸면 eval 노이즈가 0 이 된다.
4. **`sample()` 은 KV 캐시가 없고 eos 에서 멈추지 않는다.** 추론이 약 60배 낭비되고,
   생성문에 "다음 문서"가 난입한다(013 의 영문 난입).
5. **`.bat` 에서 `for %%X` 를 쓸 수 없다**(`%` 금지 규약). **루프를 펼친다** — 개별 런을 REM 으로
   골라 끌 수 있어 실무적으로도 낫다.
6. **기존 구현을 복제하지 말 것**(P029 사고). `generate.sample()` 이 샘플링 단일 소스.
7. **★CRLF 오염 — `git status` 수정 43건 중 37건이 줄끝만 바뀐 것**이다(작업트리 CRLF,
   HEAD 는 LF). 손대지 않은 `.claude/skills/*` 와 과거 로그 txt 까지 전부 잡힌다.
   `.gitattributes` 가 없고 `core.autocrlf` 도 미설정이라 반복된다.
   **`git add -A` 를 쓰면 안 된다** — 실제 변경 6건이 노이즈 37건에 묻힌다. 파일을 지정해 add 한다.

### ★Chinchilla 예산의 진짜 병목 (P033 §2)

- dense 2.65B(17.3h) + mA 1.46B(10.4h) = **27.7h**. 모든 속도 레버 성공해도 **18h**.
- **그런데 병목은 시간이 아니라 데이터일 수 있다.** 풀 ≥2× 규칙이면 dense 는 **5.3B 풀**이 필요한데,
  결과 011 이 관측한 **ko-en 한글비율 40.7%→23.0% 단조 감소**가 **한국어 소스 소진의 징후**일 수 있다.
  600M 풀에서 이미 그렇다면 5.3B 에서 50/50 은 성립하지 않는다. → **P033 단계 1 이 최우선.**
