## 3. ★bpw 회계 통일 — 무엇이 어떻게 바뀌었나

### 규약

```
안 B (정본)  삼진 = log2(3) + 16/micro_group = 1.5850 + 0.125 = 1.7100
             3:4  = 1.25    + 0.125                          = 1.3750
안 C (병기)  안 B + 컨테이너 0.274 (GGUF 가정, 역산 추정)
상주         유니크삼진 x 4B x 2벌(latent + dequant) + 나머지 fp32   ← 결과 016 실측식
```

**B 를 정본으로 고른 결정적 이유**: `log2(3) + 0.125 = 1.7100` 이 문서의 "g128 삼진 1.71" 과
정확히 일치하고 **설계 시점(가중치가 난수일 때)에 계산 가능한 고정 상수**다.
안 C 로 1.95 를 유지하려면 **학습 후에만 아는 실측 엔트로피(1.554)** 가 필요한데
`report()` 는 **학습 시작 전**에 호출된다 — 계산 자체가 불가능하다.

### 코드 변경

| 파일 | 변경 |
|---|---|
| `model/transformer.py` | 상수 4개 + `_bpw()` + `mem_breakdown(container=)` + **`mem_report_all()`** + `report()` 가 packed/packed_container/**runtime** 3줄 출력 |
| `train/trainer.py` | json 에 `packed_mb`·`packed_mb_container`·`runtime_mb`·`bpw_convention` 기록. `deploy_mb` 는 **별칭으로 유지**(구 로그 호환) |
| `eval/compare.py` | `packed_mb` 우선, 없으면 `deploy_mb` + `[구규약]` 표시 |

### ⚠️ 반드시 알아야 할 것

- **2026-07-31 이전 로그의 `deploy_mb`(30.9 / 14.9 / 11.7MB)는 구 규약**이다.
  신규 `packed_mb`(27.0 / 12.9 / 12.3MB)와 **같은 표에 넣지 말 것.**
- **재학습 불필요** — 저장 MB 는 파라미터 수의 함수라 소급 재계산이 가능하다.
- `report()` 의 **L3 상주 판정이 이제 `runtime_mb` 기준**이다(저장 기준은 오해를 부른다).

## 4. ★로그 유실 방지 — `scripts/runlog.py`

```
python scripts\runlog.py --name P036-stage1 -- python scripts\diag_trapping.py ...
```

- **콘솔 실시간 출력 + `test_result/log_YYYYMMDD_{name}.txt` 즉시 기록**
- **줄마다 flush + 2초마다 `os.fsync()`** → 정전·BSOD 에도 마지막 몇 초만 잃는다
- **`finally` 로 꼬리말 보장** — Ctrl+C·예외·이상종료 어디서든 종료코드·소요시간 기록
- **append 기본** — 배치의 3단계에서 죽어도 1~2단계 로그는 남는다
- **자식에 `PYTHONIOENCODING=utf-8` 강제** — 파이프일 때 cp949 로 떨어져 한글이 깨지는 것을 차단
- **종료코드 그대로 통과** → 배치의 `if errorlevel` 이 전부 그대로 동작 (샌드박스에서 확인)

**적용 완료**: 루트 7개 + `scripts/batch/` 8개 = **15개 배치, 총 62개 python 명령**.

> 결과문서를 쓸 때 `log_...` 를 `{번호}_log_...` 로 rename 하거나, 미리 알면 `--num 018` 을 준다.

## 5. 프리셋 승격 — `m100R1a` / `m100R1c`

```python
_m100R1a = replace(_m100, mlp_group=4, sparse34=True)    # REVIEW1 후보 A
_m100R1c = replace(_m100, mlp_group=8, sparse34=False)   # REVIEW1 후보 C
```

**기존 런에 영향이 없는 이유** (검증 완료):
1. `dataclasses.replace` 로 **`m100` 에서 한 필드만** 파생 — `m100` 자체는 무변
2. 체크포인트·로그 이름이 `{preset}_{data}_{tokens}_{tag}` → **네임스페이스 자동 분리**
3. `cli.py` 의 `--preset choices` 를 `PRESETS` 에서 자동 유도(종전 하드코딩은 `m100d` 를 빠뜨렸다)

**★선결 수정 1건** — `trainer.py` 가 `cfg.sparse34 = sparse34` 로 **무조건 대입**하고 있었다.
그대로 두면 `m100R1a` 를 써도 `--sparse34` 없이는 **3:4 가 조용히 꺼진다**.
→ `cfg.sparse34 = bool(sparse34) or bool(cfg.sparse34)` — **플래그는 켤 수만 있다.**

**운영 규칙**: 아키텍처 무관 실험(스케줄·LR·데이터·속도)은 **`m100R1c` 하나**,
아키텍처 관련(양자화·희소·패킹·메모리)은 **둘 다**. 비용 2배를 피한다.
