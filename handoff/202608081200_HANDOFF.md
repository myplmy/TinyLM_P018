## 1. ★가장 중요한 것 세 가지

### ① P042 단계0 **통과** — 그리고 **속도가 예측 밖일 수 있다**

on/off 두 런의 **전 인쇄 지표가 마지막 자리까지 일치**(결과 034). `freeze_quant()`+`drop_latent()`
는 교사 출력을 안 바꾼다. G1(초기화 정합)도 동시 통과.

⚠️ **참고값이 계획 예측과 어긋난다.** 정상상태 환산 124.7 → 99.0 ms/step = **−20.6%** 인데
계획 P1 은 **−0~5%** 를 예측했다. **이 수치는 무가치하다**(OFF 가 먼저 돌았고, tiny 라 교사 비중이
다르고, 30스텝이다). **하지만 단계1 이 P1 을 기각할 가능성**을 미리 적어 둔다 —
그러면 *"재양자화가 GPU 에서도 비싸다"* 이고 **학생 쪽 최적화 여지**가 생긴다.

→ 그래서 단계1 배치를 **2런이 아니라 3런(OFF → ON → OFF)** 으로 만들었다. `drift = OFF_B − OFF_A`
를 **먼저** 계산하게 하고, `|drift| ≈ |effect|` 면 정직한 답은 **"이 장비의 노이즈 이하"** 다.

### ② ★★DeepSeek FP8 — **우리 가중치의 FP8 오차는 원리적으로 0이다. 그런데 같은 벽에 막힌다**

어닐 완료 후 `wq = sign × α[o, g(i)]`, `sign ∈ {−1,0,+1}`, `g = micro_group = 128`.
**α 로 나누면 정확히 {−1,0,+1}** 이고 **E4M3 는 셋을 정확히 표현**한다(검산: 448 = 1.75×2⁸, 정확).
논문이 128×128 블록으로 애써 얻은 미세 입도를 **우리는 행×128 로 이미 갖고 있고**,
논문의 누산 승격 간격 `N_C = 128` 이 **우리 `micro_group` 과 일치**한다.

⚠️ **그런데 바로 그것이 벽이다.** 기술보고서 §3.3.2 원문:
*"per-group scaling factors along the **inner dimension** of GEMM ... **is not directly supported
in the standard FP8 GEMM**"* → DeepSeek 은 **CUTLASS 커널을 직접 만들었다**(DeepGEMM).

> ★★**P014B 의 U2 부정과 정확히 같은 벽이다** — *"우리 α 는 `(O, I//g)` 라 접을 수 없다"*.
> **저비트 추론 커널에서도, FP8 학습 커널에서도 막히는 지점이 동일**하다.
> 이건 우연이 아니라 **우리 아키텍처의 구조적 특성**이고, **한 번 재면 두 축에 다 쓰인다.**

→ 그래서 값싼 선행 질문 하나를 만들었다: **거친 스케일(per-row/per-tensor)로 E4M3 반올림을 받으면
얼마나 아픈가.** 학습 0·GPU 수 분. `scripts/diag_fp8_precision.py` + P022B 단계0.

**2026-08-06 의 "지금 구현하지 않는다" 판정은 유지된다.** 근거가 하나 늘었을 뿐이다.

### ③ ★`micro_group` — **저장 bpw 에 항이 둘인데 하나만 건드려 왔다**(P051 신설)

`report()` 가 찍는 식: `B: code(log₂3 / 1.25) + group scale(16 / micro_group)`

| 항 | g128 값 | 이 저장소가 한 일 |
|---|---:|---|
| code | 1.5850 bpw | P016·P034·P014 — **여러 번** |
| **group scale** | **0.1250 bpw** | ★**한 번도 안 건드렸다** |

g256 이면 **1.7100 → 1.6475 bpw(−3.65%)**, packed 13.050 → **12.573MB**, 감축비 2.07 → **2.15×**.
**아키텍처는 하나도 안 바뀐다.**

★★**직교 레버다.** g16·p1c1·E128 은 전부 **유니크 삼진 개수**를 줄이는데 이건 **파라미터당 비트**를
줄인다 → **결과 032 §8.3 의 볼록성 바깥**(용량을 안 덜어낸다)이고 **곱해진다.**
⚠️ **packed 전용** — 상주식에 bpw 가 없다(함정 1).
사전 증거: 결과 028 의 사후 g256 **Δbpb +0.0010~0.0015 = 분해능 1/5~1/8**, 그리고 **사후는 상한**이다.
**768 % 512 ≠ 0 이라 g512 는 구조적 불가 → 런 하나로 축이 닫힌다**(P045 가 g16 에서 닫힌 것과 같은 형태).

## 8. 열린 질문

- **P050 의 ①/② 분해** — P046·P048·P049 의 해석이 여기 걸려 있다(**변동 없음**)
- **결과 033 의 미분리**: 타잉 속도 이득 3.15% 가 **캐시 지역성인가 옵티마이저 대역폭인가** → B-9(fused AdamW)
- **볼록성의 반대 방향** — 용량을 **더할 때**도 볼록한가? P049 가 3점째
- ★**신규**: **P042 단계1 이 P1(−0~5%)을 기각하는가.** 기각되면 *"재양자화가 GPU 에서도 비싸다"*
  이고 **학생 쪽에도 최적화 여지**가 생긴다 — 학생은 latent 가 매 스텝 바뀌므로 단순 freeze 는 불가하나,
  **어닐 완료 후(anneal ≥ 1) 구간에서는 latent 가 여전히 바뀌는지**가 미검토다
- ★**신규**: **Ada sm_89 의 FP8 누산 가수 폭이 Hopper 의 13비트와 같은가.** P022B 단계0 으로는
  **안 보인다**(왕복만 잰다). 단계1 아니면 답이 없다
- ★**신규**: **BF16 옵티마이저 상태 254MB 를 안전하게 얻는 법.** 논문은 1T 토큰 규모로 무해를 보증하지만
  우리 `fused=True` 경로에서는 **커스텀 step 이 필요**하다
- `micro_group` **아래쪽**(g64)은 안 잰다 — 저장이 늘어나므로 방향이 반대다
