## 4. (3) ★T-MAC / bitnet.cpp 실사 → P014 재개 + P014B 신설

**보고서**: `docs/20260807_T-MAC와-bitnetcpp-실사-우리구조적용가능성분석.md`

### 4.1 원리 (한 문단)

1비트 가중치는 값이 둘뿐이라 **4개 묶음의 패턴이 16가지**밖에 없다.
활성값이 주어지면 **16가지 전부와의 내적을 미리 계산해 표에 넣고**, 가중치는
**표의 인덱스**가 된다 → 행렬곱이 **"조회 + 덧셈"** 이 되고 **곱셈이 사라진다.**
여러 비트폭은 **1비트 평면으로 쪼개(bit-serial)** 처리한다.

**어려운 점 2가지(논문이 든 것)**: ①표 접근이 무작위라 **온칩(레지스터)에 상주**시켜야 한다
②표가 온칩을 먹어서 **table quantization + mirror consolidation** 으로 줄인다.

### 4.2 T-MAC vs bitnet.cpp

| | T-MAC | bitnet.cpp |
|---|---|---|
| 대상 | **임의 저비트**(bit-serial) | **삼진 전용**(TL) + **I2_S**(int2+scale, 무손실) |
| 성능 | llama.cpp 대비 최대 **4×** | 전정밀 대비 **6.25×**, **저비트 대비 2.32×**(=T-MAC 대비). x86 **2.37~6.17×** |

**우리는 삼진이므로 bitnet.cpp 쪽이 원리적으로 더 맞는다.**

### 4.3 ✅ 맞는 것 / ⚠️ 확인 필요 / 🚫 안 되는 것

| | 항목 |
|---|---|
| ✅ | 삼진 값 집합 동일 · CPU 엣지 목표 동일 · 배치1 디코드 동일 · **병목이 역양자화로 같다** · **`mC` 를 그대로 받는다** |
| ⚠️ | **g128 그룹 스케일**(BitNet 원형은 텐서 단위) · **활성값 int8 요구 여부** · **우리 크기(dim 768)에서 이득인가**(논문은 3B급) |
| 🚫 | **`mA` 의 sparse34**(5비트/4가중치 코드북을 둘 다 모른다) · **학습은 안 빨라진다** · **평가 도구가 갈라진다** |

### 4.4 ★두 가지 중요한 함의

1. **`mA` 가 앞서는 유일한 축(저장 0.7%)은 R8 이 있어야 실물인데, R8 을 실현할 가장 유력한
   경로가 `mA` 포맷을 지원하지 않는다** → **REVIEW1 의 mC 권고가 한 단계 더 굳어졌다.**
   ⚠️ 단 이건 **도구 생태계 근거**이지 아키텍처 근거가 아니다.
2. **단계3C(언팩 캐시)는 P014 가 오면 무의미해진다** — LUT 에는 언팩 자체가 없다.

   순수 PyTorch 다. **보험이다.**

## 6. (5) ★사용자 질문 답 — LoRA·FiLM·P008 은 **서로 다른 세 가지**다

| | 추론 시 남나 | 배포 메모리 | 구현 |
|---|---|---|---|
| **①고정 LoRA**(`--lora-rank 32`) | **남는다** | 2.07× → **1.94×**(손해) | 기존 |
| **②FiLM**(`--mlp-film`) | 남는다 | 2.07× → 2.06×(**0.13MB, 거의 공짜**) | 기존 |
| **③P008 = 어닐 LoRA**(`--lora-decay`) | **사라진다**(s→0) | **2.07× 그대로** | ✅ **2026-08-07 신규** |

③은 **LoRA 를 "배포 부품" 이 아니라 "학습용 비계" 로** 쓴다.
초반 s=1 → 층별 특화(≈untied), 후반 s=0 → 순수 타잉. **삼진 어닐과 같은 원리**다.

### 6.1 "mA·mC 에서 켜서 재학습해야 하나?" — **①은 아니다**

구 데이터가 이미 답을 시사한다:

| 조건(300M 풀, g4) | val | 대비 |
|---|---|---|
| `t_base` plain | 3.9558 | — |
| `t_lora32` ① | 3.9220 | **−0.0338** ✅ |
| `t_film` ② | 3.9420 | −0.0138 ⚠️ |
| `t_kdinit` (KD) | 3.8253 | — |
| **`t_all`** (KD + ① + ②) | 3.8188 | **−0.0065** 🚫 **분해능 미만** |

> **★KD 없이는 LoRA 가 −0.0338 로 돕는데, KD 를 켜면 ①+② 를 둘 다 얹어도 −0.0065 = 구분 불가.**
> **두 기법이 같은 자리를 채우고 있다.**

**판정**: ① 권장 안 함(메모리 확실히 손해, 이득 불확실) / ② 값싸니 대조 조건으로 포함 /
**③이 진짜 실험**.

### 6.2 ★P008 의 목적이 바뀌었다

**격차는 이미 KD 가 닫았다**(결과 021: `mC` 3.7393 **<** `p6d` 3.7608).
새 목적은 **비용**이다:

| 경로 | 벽시계 |
|---|---|
