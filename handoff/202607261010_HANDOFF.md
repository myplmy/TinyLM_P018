## 3. ★삼진커널 핵심 개념 (혼동 방지)
- weight-only 삼진은 dequant 후 **dense와 동일 FLOPs** → GPU **학습**은 연산바운드라 가속 불가(스케일에서도).
  tiny(d=256)에서 k_triton≈k_off인 건 "가속"이 아니라 **둘 다 런치바운드**여서(GEMM 극소).
- 커널의 실사용처 = **CPU LUT/AVX2 배포**(P016 3:4 정합). GPU **decode(M=1)** 겨냥 시엔 SplitK/StreamK로
  업그레이드가 정답(첨부논문 arXiv:2402.00025, docs/custom_ternary_kernel.md에 기록). 학습 목적이면 저순위.
- **커널은 `--compile`과 병용 금지**(이제 코드가 강제 중단). 벤치는 `--compile` 없이.

## 4. ★데이터 풀/캐시 동작 (반드시 이해 — 토큰스윕 함정)
- Loader(`loader.py`)는 **캐시 파일 전체에서 매 배치 랜덤 오프셋**을 뽑는다. 따라서 "300M 캐시에서 100M
  소비" ≠ "600M 캐시에서 100M 소비"(표본 풀이 달라 본 데이터가 다름). prefix 성질도 균등샘플링이라 등가
  보장 못함.
- `_find_reusable`은 **tokens≥요청 캐시 중 최소**를 고른다. 현재 `ko-en_300000000`·`ko-en_600000000` **둘 다
  존재**. `--tokens 300M`은 (600M이 있어도) **300M 캐시**를 씀(최소 상위호환). 기존 300M 실험/배치 전부
  영향 없음. 600M을 쓰려면 명시(`--tokens 600M` 또는 `--pool-tokens 600M`).
- **학습토큰 = steps×micro_bs×accum×seq**. `--tokens`는 캐시 크기·이름일 뿐. 300M선 = `--micro-bs 8
  --accum 16`(유효배치 131K). "캐시 재사용 300M" 로그는 정상.
- **P007 클린판 근거**: 토큰스윕 3점을 공정 비교하려면 **모두 같은 600M 풀에서 샘플**해야(같은 풀+seed면
  100M⊂300M⊂600M 중첩, 변수=학습토큰수만). → 클린판 배치가 `--pool-tokens 600M --exact-cache`로 구현.
  단 정본 300M 결과(300M 풀)와 클린판 300M점(600M 풀)은 **직접 비교 대상 아님**(클린판은 p6* 태그 자기완결).

## 6. ★리서치 결론 요약 (학습속도·저비트, 근거 링크는 05_training_speed.md)
- **int8×int8(W1.58A8)**: 학습 비권장(소형·Ada는 2×뿐·양자화오버헤드·activation-QAT 정확도 리스크).
- **FP8(E4M3/E5M2, torchao/TE)**: 유일한 "진짜 GPU 학습가속" 후보지만 소형모델+스케일링 오버헤드로
  기대 낮음 → **P022 0단계 마이크로벤치로 게이트**(>1.2~1.3× 아니면 중단). `scripts/bench_fp8_gemm.py` 준비됨.
- **bitnet.cpp/llama.cpp**: 현재 아키텍처(SiLU-GLU·QK-norm·타잉·CLA·factorized emb) **비호환**. bitnet.cpp는
  ReLU²FFN+subln+BitLinear 요구. 교사 KD를 bitnet.cpp CPU로 돌리는 것도 무의미(batch prefill 부적합·전송병목).
- **SplitK/StreamK(첨부논문)**: 추론 decode(M=1~16) 전용. 우리 학습(M=8192, 연산바운드) 무관.
- **가장 유망한 벽시계 레버**(커널 밖): 옵티마이저 **Sophia(P023, 우리 스케일 2× 주장)**, 스케줄 **cooldown-QAT
  (P026, 저비용)**, 데이터 **P012(bpb·토큰↓)**, 교사비용 **오프라인 캐시 P019** / 압축교사 P018 / 스태킹 P024.
  엔지니어링: **`--no-ckpt`**(단일 최대), micro_bs↑, CUDA Graphs(P027, 타잉임베딩 충돌 선결).
- **2:4 준정형 희소(P025)**: 메모리+GPU속도 동시 유일 후보지만 50% 강제-0 품질리스크·소형GEMM 이득 불확실
  → 마이크로벤치 게이트.
- **WSL2**: Triton(FP8/커널/2:4)·bitsandbytes 8bit optim·fla(KDA)·expandable_segments 를 열어주나 **스필벽
  (13~14GB, WDDM)은 그대로**. 커널레벨·8bit optim·KDA 추진 시 권장, 순수 bf16 학습만이면 이득 제한.
