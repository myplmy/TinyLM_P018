## 2. ★핵심 발견 4개

### (1) KV 캐시는 정확하다 — **게이트가 오경보였다** (결과 014 §9)

fp32 teacher-forced 로짓 `max|Δ|` **1.1~1.4e-05**, argmax **100% 일치**(15프롬프트), 오차 **평탄**.
bf16 오차 0.125~0.219 는 **bf16 ULP 1~2개** — 더 작아질 수 없는 값.
**dense 가 오차 최대(0.219)인데 그리디 게이트를 통과**했다 → 실패를 가른 건 **near-tie 빈도**.

- **정본 게이트 = `scripts/diag_kvcache.py --device cpu --tol 1e-3`.**
- **그리디 문자열 비교는 게이트가 될 수 없다**(보고 전용으로 강등).
- ⚠️ **구 배치 `run_P030_infer.bat` 는 폐기.** 안내문만 고치고 **게이트 명령을 안 고쳤다** —
  다시 돌리면 같은 오경보로 멈춘다. **`run_P030_stage2B_infer.bat` 를 쓴다.**

### (2) 3:4 "희소"는 희소화가 아니고, 2.64× 는 회계 착시다 (결과 016 §7·§8)

| | 실측 |
|---|---|
| 표준 TWN 비영 | **54.4 ~ 56.8%**(0 이 43~46%) |
| 3:4 비영 | **75.00%** — 3:4 가 **덜 희소** |
| 파라미터 감소 | **0** → 상주 이득 **0** |
| 동일회계 저장 | `mA` **14.6** vs `mC` **14.7MB** = **0.7% 차이** |
| 감축비 | `mA` 2.66× → **2.11×** / `mC` **2.10× 불변** |

**1.95 = 코드 1.554 + 스케일 0.125 + 컨테이너 0.274** 로 분해 확인.
sparse34 의 **1.25 는 순수 코드공간뿐**이었다. → **다른 규약의 두 값으로 비율을 만들었다.**

> **치명도 판정: "전부 철회·재실험" 수준이 아니다**(§8). `mem_breakdown()` 은 보고 전용이라
> `val_loss`·시간·VRAM 에 영향 0. **순위도 안 바뀐다**(세 회계 모두 mA<mC<p6d). 바뀐 건 **간격**.
> **재학습 필요 런 0개.** 필요한 건 ① 코드 통일 ② 문서 정정 ③ Arenas 검증(신규).

### (3) ★Arenas 는 우리 어닐이 아니다 — **논문이 필수라 한 부품을 빼고 측정했다**

논문 §3.2 식 (7):  `Y = X·Tα + λ_t·X·W`,  식 (8): `∂L/∂X = (∂L/∂Y)(Tα + λ_t·W)ᵀ`

| | 순전파 | **역전파** |
|---|---|---|
| 우리 어닐 | `a·wq + (1−a)·w` ✅ | `.detach()` 라 **`w` 경로 없음** ❌ |
| Arenas | `Tα + λ_t·W` | **`W` 가 gradient 에 들어간다** ✅ |

Arenas 의 존재 이유가 **정확히 그 gradient 이질성 주입**(weight trapping 방지)이다.
논문 ablation 은 **3:4 뿐 아니라 1-bit·1.67-bit 순수 삼진에서도** 이득을 보고한다
→ **`mC`·`p6d` 에도 적용 대상.** → **[P036](../test_plan/P036_Arenas-잔차시냅스-weight-trapping.md) 신설**(구현 가능성 확인됨).

### (4) P028 수정 범위 = `ko-edu-en` 만 (결과 011 §0.6)

`ko-en` val 은 **건강하다**(최대 문서 2.2%, 상위10 제외 +0.020, 중위 3.805 ≈ 전체 3.7999)
→ **무작위 분할 전면 재작성(부록 A) 보류.** 전 기준선 재학습을 피했다.
`ko-edu-en` 은 거대 문서 **7개**가 토큰 37%·손실 53% → 폐기·재생성 확정.

**★단계 0.5 의 "val 23.5% 단일문서" 철회** — `eval_slices.py` 가 eos 를 **빈도 추정**(그것도
train 앞 5M 에서)해 경계를 절반만 찾았다. 실제 최대 **5.9%**. 도구 수정 완료.
