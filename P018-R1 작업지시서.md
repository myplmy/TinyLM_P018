## P018-R1 학술 실험 및 학술자료화 작업 지시서

### 0. 연구 배경

현재 약 100M parameter급 autoregressive language model을 대상으로 parameter sharing/tied MLP 구조와 knowledge distillation(KD)을 실험하고 있다.

기존 P018 실험에서 다음 현상을 관찰했다.

* `dense` KD teacher validation loss: **3.8080**
* `mC_wsd` validation loss: **3.6984**
* paired difference: **+0.1096 nats**
* `mC_wsd`를 teacher로 사용한 student `mC_ct`: **3.6764**
* 기존 `mC_wsd` student 대비 **−0.0220 nats**
* teacher 교체로 peak/reserved GPU memory가 감소
* 압축 teacher 사용 시 정상상태 training speed는 사실상 동일

그러나 이 결과에는 중요한 confound가 있다.

* `dense`는 300M training-token pool
* `mC_wsd`는 600M training-token pool
* 기존 실험에서 300M→600M token pool 증가만으로 약 0.12 loss 개선이 관찰됨

따라서 **P018의 dense vs mC_wsd 0.1096 nats 차이를 architecture superiority의 증거로 해석하지 않는다.**

또한 기존 P018은 동일 architecture/parent를 사용한 자기증류이며 seed=1이므로 일반화된 결론을 내리지 않는다.

---

# 1. P018-R1의 연구 질문

다음 질문을 검증한다.

> **Can parameter sharing reduce the memory cost of a knowledge-distillation teacher without degrading the quality of the resulting student?**

한국어:

> **Parameter sharing을 이용한 compressed/tied KD teacher가 teacher의 메모리 비용을 감소시키면서 student의 성능을 유지할 수 있는가?**

연구의 중심은 새로운 LLM architecture 자체가 아니라:

> **parameter-shared teacher의 knowledge-distillation efficiency**

이다.

---

# 2. 연구 가설

### H1 — Teacher compression

Tied teacher는 동일한 architecture family의 dense teacher보다 parameter count 및 GPU memory footprint가 작다.

### H2 — Teacher quality preservation

동일 training budget에서 tied teacher의 validation loss가 dense teacher와 사전 정의된 equivalence margin 내에 있거나, 최소한 연구 목적에 충분한 수준의 성능을 유지한다.

### H3 — KD quality preservation

Tied teacher를 사용해 학습한 student와 dense teacher를 사용해 학습한 동일 student 사이의 validation loss 차이가 사전 정의된 equivalence margin 내에 있다.

### H4 — Memory advantage

Tied teacher 사용 시 teacher의 peak GPU memory가 감소한다.

### H5 — Runtime

Parameter sharing 자체가 forward FLOPs를 감소시키지 않는 구조라면, teacher forward/training latency가 반드시 감소할 것으로 가정하지 않는다. 실제 측정한다.

---

# 3. 실험 구조

동일한 검증된 baseline Transformer architecture family를 사용한다.

```text
                 ┌── Dense Teacher ──┐
                 │                   │
Same baseline ───┤                   ├── KD ──> Same Student
                 │                   │
                 └── Tied Teacher ──┘
```

Dense teacher와 tied teacher 이외의 모든 조건을 최대한 동일하게 유지한다.

실험 matrix
| Teacher | Student | 목적                    |
| ------- | ------- | --------------------- |
| Dense   | no KD   | baseline              |
| Dense   | KD      | conventional KD       |
| Tied    | no KD   | architecture baseline |
| Tied    | KD      | 핵심                    |

# 5. Teacher quality matching

**동일 training budget에서 Dense/Tied teacher의 validation loss를 먼저 독립적으로 측정한다. 사전에 정의한 equivalence margin을 만족하는 경우에만 "quality-matched teacher" 비교로 분류한다. 만족하지 않는 경우에도 결과를 폐기하지 않고 teacher quality 자체의 차이로 보고한다.**

이렇게 해야 **결과를 보고 실험 설계를 바꾸는 circular reasoning을 피할 수 있음.**

"Teacher 성능이 거의 같다"는 표현을 사용하지 말고 **사전에 equivalence criterion을 정의한다.**

예:

[
|L_{teacher,dense}-L_{teacher,tied}| < \delta
]

여기서 (\delta)를 기존 validation resolution 또는 사전에 정한 실질적 equivalence margin에 근거하여 결정한다.

**결과를 본 뒤 margin을 변경하지 않는다.**

만약 동일 training budget에서 두 teacher가 equivalence criterion을 만족하지 못하면:

1. 결과를 그대로 보고하고
2. teacher quality mismatch를 중요한 결과로 기록하며
3. 임의로 training tokens를 조정하여 맞추지 않는다.

추가적인 teacher-compute matching 실험은 별도 ablation으로 제안한다.

# 7. Memory measurement

allocated와 reserved를 반드시 구분한다.

최소 기록:

```text
parameter_count
unique_parameter_count
peak_allocated_memory
peak_reserved_memory
```

가능하면:

```text
parameter memory
optimizer memory
activation memory
teacher latent memory
quantized weight memory
CUDA allocator state
```

도 기록한다.

**reserved GPU memory를 실제 model parameter memory와 동일시하지 않는다.**

# 8. Runtime measurement

Teacher inference time은 다음과 같이 명확히 정의한다.

* warm-up 이후
* 동일 batch size
* 동일 sequence length
* CUDA synchronization을 고려한 측정
* steady-state 기준
* 여러 step의 평균 및 분산 기록

가능하면:

1. teacher-only forward latency
2. complete KD training step latency
3. student-only step latency

를 분리한다.

# 11. 주요 비교값

단순히 `KD Efficiency = quality / memory` 같은 임의의 비율을 primary metric으로 사용하지 않는다.

**"Teacher memory −X%, student loss ΔY nats"** 만 제대로 통제된 조건에서 얻어도 상당히 좋은 empirical result.

다음 값을 우선 보고한다.

### Teacher memory reduction

[
R_M =
1-\frac{M_{tied}}{M_{dense}}
]

### Student quality difference

[
\Delta L =
L_{student,tied}
----------------

L_{student,dense}
]

### Teacher quality difference

[
\Delta L_T =
L_{teacher,tied}
----------------

L_{teacher,dense}
]

### Runtime difference

[
\Delta T =
T_{tied}-T_{dense}
]

필요하면:

> **Teacher-memory vs student-loss Pareto frontier**

를 주요 시각화로 사용한다.

# 12. 통계 분석

동일 validation examples/crops를 사용하는 paired evaluation을 우선한다.

다음 사항을 검토한다.

* paired mean difference
* standard error
* confidence interval
* paired t-test 또는 적절한 paired statistical test
* seed-level variance
* effect size

단순히 `p < 0.05`만으로 "우수하다"고 결론내리지 않는다.

**통계적 유의성과 실질적 equivalence를 구분한다.**

* "Tied architecture가 dense architecture보다 본질적으로 우수하다."
* "Parameter sharing 때문에 0.1096 nats 개선되었다."
* "Compressed teacher가 일반적으로 dense teacher보다 좋다."

이 차이는 300M vs 600M token-pool confound로 설명될 가능성이 있다.
