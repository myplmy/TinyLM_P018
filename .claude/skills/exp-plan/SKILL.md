# exp-plan

`test_plan/` 실험계획 문서를 **하나의 양식**으로 쓰고, **결과가 나오면 반드시 되돌아와 갱신**하게 한다.

## 왜 이 스킬이 필요한가

두 가지가 반복해서 어긋났다.

1. **양식이 제각각이다.** 어떤 계획서는 판정기준이 없고, 어떤 건 비용이 없고, 어떤 건
   한계를 안 적었다. 읽는 사람이 매번 다른 구조를 파악해야 한다.
2. **결과가 나와도 계획서가 안 바뀐다.** `실험계획목록.md` 만 고치고 계획서 본문은
   "미실행" 인 채로 남는다. 다음 세션이 그걸 읽고 **이미 끝난 실험을 다시 설계**한다.

## 파일명·번호

- `test_plan/P0NN_{하이픈-요약}.md` — 번호는 `실험계획목록.md` 의 최대값 + 1
- 같은 계획의 **후속 실험**은 새 번호가 아니라 **접미 문자**(`P007B`, `P021B`, `P001B`)
  → 원 계획서 안에 `# P0NNB — ...` 절로 이어 쓴다. **원본 기록을 건드리지 않는다.**
- 완료 시 `-done.md` 접미. **단 후속(B)이 필요하면 `-done` 을 붙이지 않는다.**

## 표준 골격 (이 순서를 지킨다)

```markdown
# P0NN — {제목} : {한 줄 결론 또는 목적}

> 제안 계기: {어느 결과·어느 지적에서 나왔는지. 링크}

## 1. 왜 — {지금 이걸 해야 하는 이유}
{기존 결과를 인용해 문제를 특정한다. "좋아 보여서"는 이유가 아니다}

## 2. 질문
| # | 질문 | 왜 중요한가 |
|---|---|---|
| Q1 | | |

## 3. ★예측 — 정직하게
{성공을 기대하는 이유와 **실패가 더 유력한 이유**를 모두 적는다.
 음성 결과도 정보라면 그렇게 명시한다. 이게 없으면 결과를 사후해석하게 된다}

## 4. 단계 설계 (싼 것 → 비싼 것, 각 단계가 다음의 게이트)
### 단계 0 — {선결·검증}
### 단계 1 — {...}
{각 단계에 비용·GPU 필요 여부·판정을 붙인다. 비싼 단계는 반드시 조건부로}

## 5. 판정 기준
| 결과 | 판정 |
|---|---|
{**σ = 0.012, 실무 분해능 0.024**. 그 이하 차이로 서열을 매기지 않는다}

## 6. 비용
| 단계 | 비용 | GPU |

## 7. 실행 → `run_P0NN_*.bat`
{배치가 아직 없으면 "미작성"이라고 쓴다. 있으면 파일명을 링크한다}

## 8. 한계 (반드시 함께 기록)
{이 실험이 **답하지 못하는** 것. 표본 수, 교락 요인, 일반화 범위}

## 9. 실행 이력 / 갱신
{실행일 · 결과문서 링크 · 계획 대비 무엇이 달라졌는지}
```

## 반드시 점검할 것 (계획 확정 전)

- [ ] **`exp-preflight` 를 돌렸는가?** 조건 중복·토큰 환산·태그 충돌은 그 스킬 담당이다.
      본 스킬은 **문서 양식**만 본다. 두 개는 대체 관계가 아니다.
- [ ] `docs/EXPERIMENT_BASELINES.md` 의 표준조건과 대조했는가?
- [ ] 학습토큰 = `steps × micro_bs × accum × seq` 로 검산했는가? (`--tokens` 는 캐시 크기다)
- [ ] **풀 ≥ 2× 학습토큰**인가? 다른 풀의 런과 비교하고 있지 않은가?
- [ ] 판정기준에 **σ=0.012 / 분해능 0.024** 를 반영했는가?
- [ ] **예측 절(§3)을 적었는가?** 이걸 빠뜨리면 결과를 사후 정당화하게 된다
- [ ] **한계 절(§8)을 적었는가?** "이 실험이 증명하지 못하는 것"이 비어 있으면 미완성이다
- [ ] 비싼 단계가 **싼 단계의 결과에 조건부**인가?
- [ ] `실험계획목록.md` 에 행을 추가했는가?

## ★결과가 나온 뒤 — 계획서로 돌아온다 (가장 자주 빠지는 절차)

`log-to-result` 가 결과문서를 쓴 **직후**, 다음을 이 스킬로 처리한다.

1. **계획서 §9 실행 이력** — 실행일 · 결과문서 링크 · **계획과 달라진 점**
2. **계획서 §3 예측 대조** — 예측이 맞았는지 틀렸는지 **명시적으로** 적는다.
   틀렸으면 취소선 + 이유. **이걸 안 하면 예측 절을 쓴 의미가 없다.**
3. **단계별 상태 표시** — `### 단계 1 — ... ✅ 완료(결과 0NN)` / `⏸ 대기` / `🚫 폐기`
4. **후속 단계 신설** — 결과가 새 질문을 열었으면 그 자리에서 단계를 추가한다
   (새 P번호를 남발하지 않는다 — 같은 주제면 단계로 붙인다)
5. `실험계획목록.md` 의 **대응 결과** 열 갱신
6. 계획이 **무효**가 됐으면(설계 결함 발견 등) 문서 상단에 배너로 명시한다.
   조용히 지우지 않는다 — **왜 무효인지가 다음 사람에게 필요한 정보다.**

## 한계

이 스킬은 **양식과 절차**만 보장한다. 실험 설계가 **과학적으로 옳은지, 실제로 그렇게
동작할지는 보증하지 않는다** — 그건 돌려봐야 안다. `exp-preflight` 도 마찬가지다.
양식이 완벽한 계획서도 틀린 실험일 수 있다.
