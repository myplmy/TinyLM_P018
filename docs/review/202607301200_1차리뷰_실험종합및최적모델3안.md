## ★부록 R8 — **적정 데이터 스케일은 측정하지 못했다** (2026-08-06 추가)

이 리뷰의 §4("우리가 실제로 알아낸 스케일링 그림")와 §2.1/§2.2 의 풀 관련 서술에 대한 정정·보완이다.

### R8.1 있는 그대로

> **적정 데이터 스케일(수확체감 지점, "300M 학습토큰이 132M 모델에 충분한가")은
> 이 프로젝트에서 아직 측정하지 못했다. 이유는 실험 설계나 계측이 아니라 자원이다 —
> 보유한 한국어 코퍼스(`wikimedia/wikipedia 20231101.ko`)가 약 300M 토큰에서 고갈되어,
> 데이터 풀을 늘리면 한국어 비율과 평가 셋 구성이 함께 움직인다.
> 적절한 한국어 데이터셋을 마련하지 못해 스케일 판단을 유보한다.**

### R8.2 근거

| 사실 | 근거 |
|---|---|
| 한국어 위키가 **약 300M 토큰에서 고갈**(1200M 풀에서 한국어 300.2M 에 정지) | 결과 023 §9.3 |
| 고갈 후 `_stream()` 이 **조용히** 남은 소스로 채운다(L4) | `prepare.py::_stream` |
| val = 스트림 **말미 0.5%**(L5) → **풀 크기가 val 언어 구성을 바꾼다** | 결과 006 §5.3 |
| 실측 val 한글 비율: **300M 풀 13.5% / 600M 5.5% / 1200M 0.0%** | `scripts/diag_val_lang.py` |
| `p12d` vs `p6d` 가 **자기 val 에서는 +0.0614(나쁨), 공통 영문에서는 −0.0441(좋음)** | 결과 006 §5·§6 |

**부호가 반대인데 원인은 하나다 — 언어 구성.** 풀 크기 효과는 그 아래에 깔려 분리되지 않는다.
